# Two-phase bookmark routing and Doctor evidence

## Durable lesson

A context check and a bookmarking run share the same discipline: classify from current evidence, then make the smallest explicit mutation.

- **Memory Doctor**: measure the compiled budget first. At 14,577 tokens, no compression was justified. Repair only confirmed contradictions, weak descriptions, or missing discovery links. Treat subagent findings as untrusted until their workspace and live capability assumptions match reality.
- **Raindrop**: first request collection context with the URL only, inspect the page's current title/description when classification is unclear, then save with the exact existing `collectionId`. Do not accept `Unsorted` when the user explicitly asks for categories.
- **Git boundary**: MemFS and the current project are separate repositories. Report and commit them separately. For RRR commits, stage the retrospective, learning, and derived pulse snapshots explicitly; preserve unrelated pre-existing untracked paths.

## Reusable categorization pattern

- Shader/WebGL generators → `Frontend & Design / Canvas/WebGL`
- Interactive and page-transition experiments → `Frontend & Design / Motion & Creative Web`
- React/UI libraries and design-token tools → `Frontend & Design / UI Components & Systems`
- Icon, gradient, video, and social-post resources → `Frontend & Design / Visual Assets`
- Website/OG-image inspiration directories → `Frontend & Design / Web Inspiration & UX`
- Broad curated development directories → `Learning & References / Curated Collections`

This mapping is a working default, not a reason to ignore the actual page or future taxonomy changes.
