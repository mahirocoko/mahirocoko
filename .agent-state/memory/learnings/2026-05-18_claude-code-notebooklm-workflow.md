## Key takeaways

- NotebookLM is used as a source-grounded analysis workspace: sources on the left, generated artifacts like slides, mind maps, reports, podcasts, and videos on the right.
- The video's main idea is adding Claude Code + terminal as an orchestration layer in front of NotebookLM so one natural-language command can launch multiple NotebookLM tasks.
- The advanced workflow is multi-agent: Claude checks local knowledge first, then delegates to specialized agents that create idea cards, collect official filings, run NotebookLM research, critique/fact-check, store durable insights, and generate articles/videos.
- Indexing local knowledge by type (`insight`, `transcript`, `output`) helps agents read targeted files instead of scanning everything, reducing context/token waste.
- NotebookLM does not have an official Claude integration; the video references an open-source CLI (`notebooklm-py`) as a bridge and advises checking project popularity/stars before installing.

## Apply to Mahiro Code

### What we already have
- `/watch` already covers the first step of the video's pipeline: source intake → Gemini-assisted transcript/summary → local learning file.
- `.agent-state/memory/learnings/` and `memory/slugs.yaml` already give us a lightweight knowledge base and retrieval entry point.
- Recap/retrospective habits already cover continuity; the missing part is turning raw learning notes into reusable workflow decisions.

### Useful upgrade from this video
- Treat every watched video as a **source artifact**, not a final answer. The learning note should preserve source, transcript, Gemini conversation, and retrieval hints.
- Add a second pass after `/watch`: **Insight extraction**. This pass should answer: “what should Mahiro Code do differently because of this source?”
- Keep the pipeline small before integrating NotebookLM: intake → summarize → extract durable insight → propose action/backlog → optionally update memory/skills/docs.
- Use role separation only when it earns its keep. For now, one agent can do Synthesizer + Critic in a single pass; add separate verifier/research agents when claims need external checking.

### Proposed `/watch` follow-up shape
1. **Capture**: save YouTube metadata, Gemini conversation URL, transcript, captions, tags, retrieval hints.
2. **Synthesize**: short summary + key ideas in Mahiro's working language.
3. **Extract**: durable insights, workflow implications, and risks.
4. **Route**:
   - update memory/skill if it is a repeatable behavior;
   - add backlog if it is an implementation idea;
   - leave as learning note if it is only contextual.
5. **Verify**: if the note recommends tools/dependencies such as `notebooklm-py`, research the repo/security/auth first before adoption.

### Candidate actions
- Add a reusable section template to future `/watch` notes: `Apply to Mahiro Code`, `Durable insights`, `Candidate actions`, `Adoption triggers`.
- Consider a small `/watch --extract` or follow-up script later that reads the latest learning note and appends this second-pass section automatically.
- Do not integrate NotebookLM CLI yet. Adoption trigger: at least 2-3 repeated research workflows where Gemini/local notes are not enough and source-grounded NotebookLM artifacts would materially help.

### Risks / cautions
- NotebookLM CLI is unofficial; check auth handling, token/session storage, maintenance, and repository trust before running it against personal Google data.
- Multi-agent pipelines can become ceremony. Prefer a boring, reliable local note pipeline until the bottleneck is proven.
- Learning files only help if retrieval works. Tags, slugs, and concise “why this matters” sections matter more than storing huge transcripts.
