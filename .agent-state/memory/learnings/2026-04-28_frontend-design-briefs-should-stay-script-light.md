# Lesson Learned: Frontend design briefs should stay script-light

**Tags**: frontend-design, skills, prompt-workflow, uncodixify, asset-workflow

When a design skill works with visual references and prompt corpora, the durable boundary is `script = scaffolding`, `docs = judgment`, and `agent = synthesis`. The script should keep repeatable mechanics deterministic: list prompt assets, compose prompt stacks, validate repo-local paths, and print a brief scaffold. It should not become a heuristic extractor, taste classifier, or pseudo-generator because reference interpretation depends on product intent, brand constraints, hierarchy, accessibility, and restraint.

Motionsites-style prompts are useful as a specificity corpus, not as aesthetic canon. Borrow section contracts, font roles, media/background roles, motion timing, fallback detail, and implementation constraints. Filter liquid glass, pill navigation, cinematic dark SaaS, giant video heroes, hover scale, glows, and generic premium gradients through `uncodixify`. Use `asset-designer` for multi-asset planning and delivery manifests, and use `web-asset-prompts` for individual generated-image prompt specs.
