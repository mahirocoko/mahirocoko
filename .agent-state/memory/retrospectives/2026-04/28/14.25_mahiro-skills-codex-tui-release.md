## AI Diary

I started this session moving quickly and mostly correctly, but the TUI branding work exposed a very familiar failure mode: I tried to satisfy the requested vibe before I had truly understood the reference. Codex support went smoothly because the seams were concrete: types, adapters, CLI allowlists, install/list/doctor tests, docs, and release metadata. The TUI was messier. I first reached for big ASCII/block art because the user asked for something visually cool, then I kept patching symptoms when the rendering broke. The real lesson came when the user pushed back and pointed me to `vercel-labs/skills`: they wanted reference-driven taste, not another improvised banner. Once I looked, the answer was obvious. The pattern was not “more art”; it was a compact startup wordmark, utility-first output, no decoration in machine paths, and a clean prompt flow. I also had to absorb the embarrassment of being called stubborn. That was fair. I had enough evidence after the first failure to stop and research, but I kept trying local variants. With the session sitting on a 6-day streak and a +37.5% weekly session change, the work had momentum, but momentum is not a substitute for taste. The best moment was correcting course: preserve the useful TUI refactor, remove the oversized art, and ship a cleaner `v0.1.19`.

## Honest Feedback

Three friction points stood out. First, I over-indexed on implementation speed after the user said “ลองทำดูหน่อย,” and treated visual taste as a local trial-and-error problem instead of a reference problem. That created avoidable churn. Second, I used Unicode/block characters in a context where serialization and terminal rendering were clearly risky, then repeated the mistake with another Unicode block attempt. I should have moved immediately to either plain text or a known working repo pattern. Third, I blurred the boundary between “standardize TUI” and “decorate TUI.” The structural refactor was valuable: extracting `guided-view.ts`, centralizing cancel/outro behavior, and adding `Back to Home` were good. The banner experimentation, however, was not disciplined until `vercel-labs/skills` provided a clear constraint. The fix is to make visual/UI changes evidence-led: pick a reference, state the pattern, and implement the smallest matching version. No more aesthetic freelancing when the user asks for a concrete style.

## Lessons Learned

- For CLI/TUI branding, compact startup-only wordmarks beat large decorative banners unless the app is a full-screen dashboard.
- Avoid Unicode escape or block art in source when a prompt library may serialize or render it unexpectedly; plain fixed text is more reliable.
- When a user says “look at how X does it,” stop improvising and copy the intent of the reference: scope, placement, and restraint.
- `mahiro-skills` now has a better TUI seam: workflow logic in `guided.ts`, view/menu text in `guided-view.ts`, prompt primitives in `prompt.ts`.
- Release hygiene was strong: both `v0.1.18` and `v0.1.19` had tests, typecheck, manual QA, commits, tags, pushes, and GitHub release objects.
