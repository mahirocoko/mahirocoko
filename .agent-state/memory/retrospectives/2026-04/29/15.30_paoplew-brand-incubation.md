## AI Diary

I felt this session turn into a useful correction of my own naming instincts. At first I was too willing to recommend names from vibe alone, especially `Flowmint`, because it fit the lab04 cashflow feeling cleanly. The user immediately pushed the right constraint: check whether it is already used. Once I researched it, the name collapsed under real conflicts, including direct finance usage. That changed the whole posture of the session. The best moment was when the user said every recommendation should come with research. That is exactly the kind of operating rule that prevents brand work from becoming pretty fiction. I also noticed how easily Thai-inspired names can become either too literal and collision-prone or too coined and unreadable. The path to PaoPlew worked because it came from repeated constraints: Thai-ish but not touristy, playful but not childish, readable but not generic, and researched before being treated as a candidate. With a +128.6% weekly session change in the pulse data, the project has a lot of creative velocity right now, and this session helped convert that velocity into a concrete repo seed instead of another floating idea.

## Honest Feedback

Three friction points stood out. First, I should have applied conflict research before the very first brand recommendation instead of waiting for the user to ask. The later scans were thorough, but the initial Flowmint suggestion created avoidable rework and showed that naming needs a research-first workflow by default. Second, I briefly over-produced coined names that were lower collision risk but less readable. That was technically sensible but emotionally wrong for the product, and the user had to pull the direction back toward modern playful language. Third, the documentation migration crossed two repos, which always creates coordination risk. I removed the temporary main-repo brand guide after moving it into the incubated repo, but the main repo still has the incubate symlink and local memory metrics, while the paoplew repo has its own README and docs changes. Future wrap-up should be careful about commit boundaries so the canonical guide is committed in the new repo before any cleanup commit in the parent repo.

## Lessons Learned

- Brand names should be researched before recommendation, not after the user gets attached.
- Readability is a first-class naming constraint; low-collision coined words can still fail if they feel awkward.
- Thai flavor works best here as sound, warmth, and concept, not as direct common finance words.
- Incubated repos should own their canonical product documents once they exist.
- Stack decisions should stay explicitly TBD until product and brand foundations are stable.
