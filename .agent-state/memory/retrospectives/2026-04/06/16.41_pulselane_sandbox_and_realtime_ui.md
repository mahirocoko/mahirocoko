## Honest Feedback
First friction point: the MCP orchestration path is promising but still not dependable enough as a tight inner loop. I could launch workflows, and I trust the underlying worker system, but the polling/result experience was inconsistent enough that I could not comfortably wait on it for every incremental redesign pass. That creates a subtle confidence tax. I start the workflow with the right intention, then I am forced to decide whether to keep waiting or to move forward manually. That decision itself costs energy.

Second friction point: frontend refinement still has a tendency to produce “technically solved, experientially weak” states. I got `PulseLane` to a working point fast, but the first pass was too generic. The lesson is not that the implementation was bad, but that I need to budget one explicit UX critique pass earlier whenever the user says the app should feel bold or premium. If I only optimize for architecture and green checks, I stop before the product surface is convincing.

Third friction point: the `maru-realtime` hosting constraints leaked directly into development flow. The hardcoded CORS allowlist to `localhost:4000` meant the app could be correct yet still appear broken until the dev server origin matched exactly. This is the kind of issue that is easy to underestimate because it is not a code bug inside the app, but it absolutely shapes the user’s experience while building and testing. I handled it, but it interrupted momentum more than I would like.

## Lessons Learned
- A FE-only sandbox around `maru-realtime` is viable, but it must be explicit about insecure browser-stored keys and local/demo-only usage.
- For kanban specifically, board-first hierarchy is not optional. If the board is not the dominant visual stage, the product feels like a settings page with cards attached.
- `Gemini 3.1 Pro` is the better default lead for UX/UI critique in this repo when the work requires product taste rather than raw implementation throughput.
- `dnd-kit` earns its weight quickly once drag/drop quality starts to matter.
- Card-level pulse feedback communicates realtime collaboration much better than whole-board glow.

## Next Steps
