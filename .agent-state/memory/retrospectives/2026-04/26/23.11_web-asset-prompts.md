## AI Diary

I started this session by treating the user’s request as a straightforward image-asset generation task, but the environment immediately forced a constraint: there was no built-in image generation tool exposed and no `OPENAI_API_KEY` available for fallback CLI generation. My first response was practical but incomplete; I prepared a prompt queue instead of actual images. The more important shift happened when the user challenged the quality of the generated images and said they were hard to use on the web. That exposed a blind spot in my initial asset prompts. I had written them like tasteful image-generation prompts, not like production web asset specifications. The distinction matters. A beautiful still image can be useless if the product is clipped, the background cannot be removed, the crop fights responsive layout, or there is nowhere safe to overlay text. I then created a skill to encode that lesson locally. I am satisfied that the v0 skill captures the core failure mode, but I also know it is still a foundation rather than a mature quality system. The useful lesson is not just “add ratio”; it is “decide the asset’s web role before prompting.”

## Honest Feedback

First friction point: I let the initial `asset-prompts.jsonl` become too image-aesthetic-driven. It had strong mood direction, but not enough operational constraints for real layout use. Second friction point: because the image backend was unavailable, I pivoted to prompt preparation, but I did not immediately distinguish between placeholder generation prompts and final production prompt doctrine. That made the first artifact weaker than it should have been. Third friction point: the new skill is useful, but it is still too lightweight if judged as production-grade. It has modes and checks, but no fixture-based validator, no backend-specific prompt tuning, and no automatic rewrite path for a lab asset manifest. The user’s skepticism was warranted. I should have said earlier that the skill was a v0 codification of the discussion, not a final answer to professional asset generation. The positive side is that the conversation found the real rule: prompts must encode how the asset will be consumed by CSS, cards, overlays, and responsive crops.

## Lessons Learned

- Website image generation prompts must begin from asset role, not visual subject.
- Transparent cutouts need strict instructions: isolated object, no background, generous padding, clean silhouette, no cast shadow, no floor plane.
- Full-bleed photos need ratio, crop safety, safe negative space, and edge discipline.
- A prompt can be aesthetically detailed and still fail as a production web asset prompt.
- A skill that turns this into reusable doctrine is valuable, but it needs validators and fixtures before it becomes dependable.
