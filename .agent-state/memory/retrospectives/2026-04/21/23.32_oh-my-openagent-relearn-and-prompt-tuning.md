That created cleanup work and forced a second learn pass. The second friction point was that delegated research results were not enough on their own. That meant I still had to materialize missing files manually and then verify the final state. The third friction point was prompt-layer complexity. By the time I had traced the recommendation-first mismatch, I was looking across local `CLAUDE.md`, built-in OmO prompts, delegated planner prepend logic, and config overrides simultaneously. The system is powerful, but it is also layered enough that it is easy to misattribute a behavior to the model when the real cause is a stronger prompt instruction buried lower in the stack.

## Lessons Learned
- In a learn workspace, “pull” should be interpreted literally at the canonical source behind `origin` unless the user explicitly approves an alternate workflow.
- OmO behavior often comes from stacked prompt layers, not from a single agent file or the model alone.
- Prometheus is the first suspect for option-heavy planning responses; Hephaestus and Atlas are better used as negative controls for this issue.
- Delegated subagent reports still need filesystem verification.
- Recommendation-first tuning works best when applied to both `sisyphus` and `prometheus`, because planner behavior can bypass orchestration style preferences.
