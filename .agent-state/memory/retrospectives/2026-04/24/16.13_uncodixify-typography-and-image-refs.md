## AI Diary
I felt the value of real feedback strongly in this session. The earlier `uncodixify` doctrine looked good on paper, but the user's actual trial exposed that “restraint” language was still too soft. I had added rules saying not every page needs display typography and that scale should be the last amplifier, but the model still found room to produce giant headings. That made the next move obvious: the skill needed enforcement language, not just taste language. The shift from “Typography restraint” to “Hard typography enforcement” felt important because it names the behavior we want the agent to follow when another prompt says “dominant,” “editorial,” or “typography-first.”

The GPT Image discussion also clarified a mental model I want to remember: image models are not page-layout engines. They optimize for a complete composition inside a fixed ratio. If we ask for a full long page in one image, the model will compress spacing before it gives up content. That explains why section padding kept collapsing even after the prompt asked for more breathing room. The better approach is not infinitely stricter wording, but changing the unit of generation: upper page, mid page, lower page. That is a practical lesson because it changes workflow, not just phrasing. The session felt productive because every change came from observing a failure and naming the failure mode precisely.

## Honest Feedback
First friction point: I initially treated the prompt issue as if stricter wording alone would solve it. The later observation that GPT Image compresses long pages into one ratio was more useful than another round of adjectives. This is a reminder that some model failures are structural, not linguistic.

Second friction point: the typography doctrine required more force than I first gave it. “Restrained” and “not oversized” are too interpretable. When prompt stacks include words like dominant, editorial, expressive, or typography-first, the model needs explicit conservative reinterpretation rules.

Third friction point: the working tree is now carrying both committed and uncommitted design artifacts. The main doctrine commit is done, but there are remaining image/lab artifacts and updated retrospective metrics. The content is valuable, but the repository needs a cleanup decision soon so these support files do not blur the main change set.

## Lessons Learned
- If an image model compresses spacing, split the page into smaller reference clusters instead of only adding stronger spacing adjectives.
- Typography guardrails must be explicit and operational: one dominant zone, conservative reinterpretation, reduce size first.
- Prompt systems need feedback loops from actual generations; doctrine that looks good before testing may still be too soft.
- Image references should guide implementation direction, not serve as exact scroll-pacing proof.
