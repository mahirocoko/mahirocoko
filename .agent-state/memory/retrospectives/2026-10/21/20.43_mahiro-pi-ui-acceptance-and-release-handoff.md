## Honest Feedback

1. **Review coverage arrived late.** Multi-file patches and malformed hunk counters should have been adversarial inputs before the first polished handoff. Renderer geometry alone cannot establish that the displayed history is truthful. The repair and independent reproduction were necessary, not optional polish.
2. **Evidence tooling caused avoidable delay.** The no-newline escape bug was in the verifier harness. Stopping was safer than mislabeling a product regression, but requiring another parent turn for a routine ignored-fixture correction added friction. A corrected byte-validated fixture, original evidence retention and one bounded rerun were sufficient.
3. **Ownership and status needed precision.** A preview reload is not broad activation, automatic memory activity is not a coordinator-authored save, and technical passes are not human acceptance. The final source-inventory comparison also initially used a different untracked-file mode; matching the verifier's command resolved the metadata mismatch without source changes. Future release work must use current union evidence rather than recycling the earlier UI-only test totals.

## Lessons Learned

These are retrospective observations, not new rules:
- Structured diff presentation needs validated boundaries and counts; truthful raw fallback is better than confident misinterpretation.
- Check host settings before building a second implementation of startup behavior.
- Keep product defects, fixture defects, source readiness, runtime activation and human acceptance distinct.
- Return source/heavy ownership explicitly, and hand a release to its existing project owner rather than opening a competing writer.

No separate reference learning was created: existing one-writer, public-API, truthful-evidence and repo-reality guidance already covers the transferable decisions. **Retrospective-only; no durable lesson promoted.**
