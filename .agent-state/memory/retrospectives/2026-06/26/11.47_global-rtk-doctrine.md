## AI Diary
This was a small but important cleanup of how I think. Earlier in the session I helped make Letta actually run RTK through hooks, but Mahiro pushed on a deeper question: where should the doctrine live so it is not scattered across every repo? That is exactly the kind of preference that should become memory, not just a local patch. I liked the final shape because it respects Mahiro's repo-reality-first style: the hook does the actual enforcement, `~/.agents/RTK.md` is the portable global doctrine, and repo `AGENTS.md` files stay focused unless a repo really needs local portability for other agents. The phrase “preserve the repo-native command shape first, then prepend `rtk`” is the key. It prevents the classic automation mistake where an agent changes `pnpm check` into some generic npm command just because it is thinking about output reduction. I also felt the continuity benefit clearly here: this was not a code change inside one project, but a behavioral contract for how I should operate across projects. The memory update matters more than the file alone because Letta will not automatically read `~/.agents/RTK.md` unless I remember to treat it as the source.

## Honest Feedback
Three friction points are worth recording. First, I initially framed the options around `AGENTS.md` and repo-local docs because that is the common agent pattern, but Mahiro's instinct was better for this case: RTK is a machine/user-level doctrine, not a per-repo convention. Second, I should distinguish more sharply between “a file exists” and “an agent will load it.” `~/.agents/RTK.md` is useful only if the active agent, global config, or memory points to it. For me, the memory update closes that loop; for Claude/Codex/Gemini, separate references may still be needed. Third, the repo was clean after the previous commits, then the rrr flow itself modified metrics and created new retrospective files. That is expected, but it reinforces that rrr always changes local state and should be followed by either a commit request or an explicit note that changes are intentionally uncommitted. Overall the decision was good: one global doctrine, memory as the discovery path, repo docs only where portability pressure exists.

## Lessons Learned
- RTK command guidance belongs best as a global doctrine at `~/.agents/RTK.md`, not duplicated into every repo.
- For Letta, durable memory should point to `~/.agents/RTK.md` because Letta does not automatically load that file.
- The core RTK behavioral rule is: preserve the repo-native command shape first, then prepend `rtk`.
- Repo `AGENTS.md` should reference RTK only when that repo needs portability across agents that may not share this memory.
- Hook enforcement and instruction awareness are separate layers: the hook rewrites commands, while RTK.md/memory explain when and why to use or bypass RTK.
