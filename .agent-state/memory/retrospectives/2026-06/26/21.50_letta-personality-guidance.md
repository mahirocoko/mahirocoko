Three friction points stood out. First, I gave useful explanations but did not verify the underlying `/experiments` implementation in source during this turn, so I should treat the experiment descriptions as UI-label-based interpretation rather than deep source-confirmed behavior. Second, the personality list had repeated labels like “Letta Code” with different descriptions; I inferred intended use from the descriptions, which is practical but not the same as reading the actual templates. Third, I should be careful when recommending `Blank` for a novel agent to pair it with concrete next artifacts: a persona draft, memory schema, canon files, and the `thai-novel-reader-experience` skill. I mentioned these, but the next actionable step could have been more explicit. Overall the advice was directionally right: keep the main agent stable, create a separate novel agent for creative writing, and choose personality based on the agent's job rather than novelty.

## Lessons Learned
- In Letta Code, personality should be explained as a persona/template swap for the same agent, not as creating a new agent.
- A separate agent implies a separate agent id, memory, recall/history, and durable self.
- For Mahiro Code, keep the memory-first personality because it matches the main persistent coding companion role.
- For a dedicated Thai novel agent, prefer `Blank` plus a custom persona and memory structure over coding-oriented personalities.
- Treat experimental feature flags conservatively; explain safe-to-try flags separately from runtime/context-affecting flags.
