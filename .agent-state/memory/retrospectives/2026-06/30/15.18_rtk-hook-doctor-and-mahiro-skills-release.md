## Architecture Decisions

- Keep `doctor-hooks.py` under `~/.letta/hooks/` because it diagnoses the local Letta runtime, not a project repo.
- Avoid auto-repair in the doctor for now. It only reports health and smoke-tests the adapter; settings repair should stay explicit because hook config controls security-related behavior.
- Preserve the restored `hooks` shape as top-level global settings rather than project-local `.letta/settings.local.json`, because RTK/security hooks should apply across repos.
- Treat RTK log absence as a first-class signal. If there is no new `rtk-letta-rewrite.log` activity for a whole day while shell tools are being used, suspect hook registration before blaming RTK itself.

## Lessons Learned

- If RTK stops appearing, first check whether `hooks` disappeared from `~/.letta/settings.json`; absence of new rewrite log entries is a stronger signal than individual no-rewrite entries.
- Keep a direct hook smoke payload handy for Letta's `exec_command` shape (`tool_input.cmd`), because it bypasses the runtime matcher and proves whether the adapter itself works.
- For global Letta runtime guardrails, local doctors are valuable even when the underlying scripts are small.
- Settings repair should create a timestamped backup first, because `settings.json` contains many agent/session records.
