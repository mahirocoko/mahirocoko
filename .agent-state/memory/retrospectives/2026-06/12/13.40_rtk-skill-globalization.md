## Honest Feedback

Three friction points stood out. First, I answered the `.rtk/` concern one step too abstractly before actually simplifying the file; Mahiro had to correct that the line still did not match the intent. The recovery was quick, but the better behavior is to remove confusing optional caveats when the user clearly says the thing is unnecessary. Second, skill root management still depends on explicit human reminders. Letta's available-skill surface does not automatically include `~/.agents/skills`, so I need to preserve that as a real operational gotcha, not a vague memory. Third, shell environment assumptions bit once: the first symlink script used `basename` under a shell/path where it was unavailable, then I reran with parameter expansion under Bash. That was harmless, but for durable admin-ish tasks I should prefer POSIX-safe shell patterns or explicitly choose Bash when using Bash arrays/features.

## Lessons Learned

- RTK guidance belongs in shared context as a short command-output policy, not as a large Claude-specific instruction dump.
- `~/.agents/skills` remains Mahiro's global cross-agent skill source, while Letta currently needs `~/.letta/skills` entries or symlinks to discover them.
- When a skill is accidentally installed into workspace `.claude/skills`, move it to `~/.agents/skills` if Mahiro wants it globally, then symlink it into Letta.
- For installed CLI provenance, `command -v`, `ls -la`, and `realpath` are more reliable than `npm prefix -g` when NVM/Homebrew Node coexist.
