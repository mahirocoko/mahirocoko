The sprite pack work started with a lot of uncertainty: some results looked wrong, some GIFs appeared to smear frames, and Codex imagegen kept returning inline payloads instead of normal files. ## Honest Feedback

Three frictions stood out. First, I was too willing to use an available image as source material when the user only intended it as reference. That produced a polished but conceptually wrong avatar/card pass. The correction is now explicit in memory, but I should have asked or defaulted to “new image in this style” as soon as Mahiro said `ref`. Second, Codex imagegen lanes are helpful but noisy: when they cannot find saved files, they sometimes rewrite existing assets or copy stale cache files. I had to kill lanes and extract payloads manually. Future sessions should assume inline imagegen output needs provenance checks before touching project files. Third, I accumulated too much narrative in `mahirocoko/context.md`. The details were true, but not all belonged in compact repo memory. I need to separate current repo context from durable technique notes earlier, using sprite-forge files for general lessons and keeping project memory lean.

## Lessons Learned

- Reference-only images must stay reference-only unless Mahiro explicitly asks to reuse the pixels.
- GIF previews can lie if disposal is wrong; runtime strips/contact sheets are the source of truth.
- For AI sprite generation, one action at a time plus strict runtime contracts beats large multi-action sheets.
- Character concept changes, such as quadruped run -> bipedal sword-run, require regeneration from the right skeleton rather than timing trims.
- Project memory should stay compact; general technique lessons belong in focused reusable memory files.
