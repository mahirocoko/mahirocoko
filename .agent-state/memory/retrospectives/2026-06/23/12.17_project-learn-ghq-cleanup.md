## AI Diary

This was a small maintenance task, but it mattered because it touched destructive filesystem behavior outside ordinary source edits. I felt the pull to “just delete the list” because Mahiro's wording was clear, but I also remembered that learn/incubate cleanup can accidentally destroy active work if I treat symlinks and clones as interchangeable. The dry-run checkpoint was the right move. It gave Mahiro a chance to narrow the cleanup from “everything learn” to a specific list, and it helped me avoid deleting incubated projects or work repos such as eizypay and haabiz landing. The most uncomfortable moment was the `shutil.rmtree` failure on a symlink directory. It was a good reminder that Python cleanup logic is not automatically safe around symlinks, and a partially failed destructive operation can leave state halfway changed. I had to recover carefully: rerun idempotently for learn entries, then separately delete ghq clones from the original targeted path list because the selection logic no longer had the removed learn entries to infer from. I think I handled the recovery transparently and verified the end state, but the better future implementation is to write the target plan to a file before deleting anything so recovery does not depend on reconstructing from conversation text.

## Honest Feedback

1. The dry-run and confirmation loop was correct, but I should have persisted the exact cleanup plan as a temporary JSON or markdown artifact before execution. When the first delete pass failed midway, the source-of-truth target list had already partially disappeared from `.agent-state/learn`, so I had to use the previous dry-run/path list to finish ghq clone deletion. That worked, but a saved execution plan would be safer and more auditable.

2. My initial cleanup script used `shutil.rmtree` on learn entry directories without checking whether the entry itself was a symlink. That is a subtle but important filesystem bug. In this repo, some learn entries were symlink-like directories, and Python correctly refused to rmtree them. Future cleanup scripts should use a `remove_path` helper from the start: unlink symlinks/files, rmtree real directories only, and refuse paths outside expected roots.

3. I did not create a commit because Mahiro did not ask. That matches policy, but it also means the maintenance record lives in `.agent-state` uncommitted until explicitly committed. If Mahiro wants cleanup history in git, the follow-up should be a focused commit for these rrr files and metrics only; there are no source changes from the cleanup itself.

## Lessons Learned

- Treat project learn/ghq cleanup as destructive maintenance even when the user asks casually.
- Always inventory learn/incubate overlap first; preserve incubate targets by default.
- For targeted cleanup, perform a dry run and ask confirmation before deletion.
- Persist or keep the cleanup plan before deleting, because partial failures can remove the discovery data needed for retries.
- Use symlink-aware deletion: `unlink` symlinks/files, `rmtree` real directories only.
- Verify after cleanup with project counts, broken-link count, selected ghq path checks, and `git status`.
