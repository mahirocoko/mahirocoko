I handled it by falling back to direct tools, but it reduced breadth and made the workflow feel more manual than intended. Second, the `/watch` skill documentation assumed scripts existed in the repo-local `src/skills/watch/scripts/` path, while the real scripts lived under the installed skill directory in `~/.config/opencode/skills/watch/`. That mismatch caused a failed first pass and broke flow until I re-located the scripts. Third, the learning pipeline is still slightly fragmented. The watch flow, Gemini conversation, local learning notes, Oracle indexing, and public-summary output all work, but they do not yet feel like one seamless command. I had to manually bridge between transcript capture, note authoring, Thai summary creation, and post drafting. Nothing was blocked, but the edges are still showing. The good news is that all three frictions are visible patterns now, not vague discomforts.
