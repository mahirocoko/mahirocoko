## AI Diary

หลัง realign งานเริ่มเดินตรงขึ้น การตรวจ installed runtime ทำให้เห็นความไม่สอดคล้องที่สำคัญ: prompt บอกให้สร้าง clickable Markdown link แต่ renderer ยังแสดง target เต็มในวงเล็บอยู่ ตรงนี้อธิบายได้ทั้งเรื่อง path เปิดได้และเรื่องบรรทัดตก การทดลองทีละตัวแปรช่วยมาก—`.tsx` แบบ path-only เปิด VS Code, JSON/Markdown ไป Xcode เพราะ UTI, ส่วน `:line` ล้มเหลวไม่ว่าจะใช้ `~` หรือ absolute path สุดท้ายผมพอใจกับการยอมรับข้อจำกัดแทนการพยายามทำให้ทุกอย่าง “สมบูรณ์” ด้วย local runtime patch ที่เปราะง่าย เซสชันนี้เตือนชัดว่า integration ระหว่าง app, multiplexer, terminal และ OS opener ต้องพิสูจน์ ownership ทีละชั้น และ human choice เรื่องความเสถียรสำคัญกว่าความสามารถที่ดูหวือหวา

## Lessons Learned

- เริ่มจาก gesture และ owning layer ให้ชัด: assistant renderer, tool card, Herdr, Ghostty หรือ LaunchServices เป็นคนรับผิดชอบการเปิด
- `Read(...)` card ที่แสดง path ครบไม่ได้แปลว่า assistant Markdown มี OSC-8 ทั้งสอง surface ใช้คนละ contract
- ใน Letta Code 0.30.28 Markdown file link ถูก render เป็น visible `label (target)` จึงไม่เหมาะกับ path ยาวใน terminal แคบ
- Plain path opener เปิดได้เฉพาะไฟล์จริง การเติม `:line` หรือ `:line:column` ทำให้ชื่อ path ไม่ตรงไฟล์และเปิดไม่ได้
- ถ้าห้ามแก้ upstream ให้ใช้ complete path-only contract: path หนึ่งครั้ง, `~/...` ใต้ home, line แยก และไม่อ้างว่า focus line ได้
- macOS association แยกตาม UTI การตั้ง `public.source-code` อย่างเดียวไม่ครอบ specific types เช่น JSON, Markdown, JavaScript หรือ Python
- เมื่อพบ scope correction ให้ถอนการเปลี่ยนแปลงที่ผิด boundary ก่อน แล้วค่อยหา local extension point ไม่ควรพยายามรักษางานเดิมไว้เพียงเพราะทำไปแล้ว
- RRR ownership ต้องตามเจ้าของบทเรียน ไม่ใช่ cwd ชั่วคราว โดยเฉพาะงานที่ตรวจ upstream repo เพื่อแก้ workflow ส่วนตัว
