## AI Diary

I began this session with a familiar mistake: I had enough memory to produce a plausible framework, so I moved too quickly from diagnosis to structure. The first recommendation was coherent, but it was still my synthesis of Mahiro rather than Mahiro describing his actual working sequence. When he asked me to slow down and let him tell the workflow again, the quality of the work changed immediately. His version was much more concrete: start a new frontend project with `mahiro-style`, establish local docs, make semantic search safe, learn from useful repositories when blocked, retain lessons through `rrr`, and commit through a project-aware procedure. That evidence revealed that “new versus existing” was not two separate workflows; it was two entry modes into one loop.

The second meaningful correction was about execution. I initially described Agy, Cursor, Codex, and Pi as execution specialists, which silently equated delegation with direct CLI. Mahiro corrected that the main agent may simply do the work, or use Letta subagents without opening an external pane. This led to a much more truthful escalation path: main first, Letta subagent when context or role needs separation, and direct executor only when a provider-specific capability or environment is useful. The deck improved because each correction removed ceremony rather than adding another layer. I should carry that instinct forward: ask for the lived sequence, distinguish mechanism from purpose, and add orchestration only when the work provides a reason.

## Honest Feedback

First, I spent too much effort polishing the old narrative before challenging whether the narrative itself matched the talk's job. The visual work was competent, but polishing Slide 7 or Slide 8 could not fix a deck whose first half answered the wrong question. Second, after identifying the narrative problem, I still tried to solve it from persistent memory before giving Mahiro enough room to describe the current workflow in his own words. That produced a polished abstraction too early. Third, my first tools map treated external direct CLIs as if they were the normal execution layer. This was technically plausible but operationally false; Letta Code can handle a bounded task directly or delegate internally. The better process is evidence first, one proposed sentence of thesis, then a content skeleton, and only then a visual rewrite. I also need to verify installed skill contracts before projecting command variants. The stale `rrr --store` wording survived because remembered history outranked the current packaged skill until the Thai reviewer challenged it.

## Lessons Learned

- For a personal workflow talk, the human's lived sequence outranks a framework reconstructed from memory
- New and existing code work may differ only at context entry, not across the entire execution loop
- Main execution, internal subagents, and direct CLI are separate layers; do not collapse them into one “specialist” category
- Tools should be shown by job and escalation trigger, not as a product-history inventory
- Current installed skill contracts must outrank historical command vocabulary
- Minimal Q&A and consistent dark bookends fit this deck better than explanatory closing copy or alternating paper surfaces
