## AI Diary

I entered this session believing the hardest part would be writing a rigorous coordination skill, but the more important lesson came from watching a technically correct workflow fail at the visual gate. The skill did several things well: it stopped K3 before writing when the image channel hallucinated an unrelated crypto page, it preserved hash-bound raw evidence, and it blocked Sol after both human rejections. Those controls prevented a bad candidate from quietly becoming production work. That is real value, even though neither page survived.

My main mistake was treating model substitution as a reasonable continuation before fully preserving Mahiro's intended ownership experiment. Gemini could see the images, so I let Gemini implement. The result may have been mechanically competent, but it tested the wrong hypothesis. Mahiro corrected that immediately. I then followed the approved Gemini-prompt-to-K3 route exactly, including YOLO, receipts, clean desktop/mobile renders, and no main-authored visual rewrite. The second rejection was therefore more informative: a correct ownership chain and a grounded intermediary prompt still did not transfer source taste well enough.

I also felt the operational drag of weak capture assumptions. HiroHiro selector screenshots carried instrumentation, while a Playwright `networkidle` wait hung against Astro dev/HMR until I replaced it with a bounded eager-image capture. Those are solvable mechanics, but they consumed attention that should have stayed on the experiment. The final cleanup was important: preserving evidence is useful until Mahiro explicitly decides it is no longer worth keeping. Once he asked to delete it, the right action was targeted removal, not defending the experiment or keeping bulky rejected apps around “just in case.”

## Honest Feedback

1. **I changed the tested ownership route too early.** After K3's image channel failed, I selected Gemini as visual owner because the skill was model-agnostic. That was internally logical but missed Mahiro's actual experiment: he wanted K3 to own the implementation. I should have surfaced the channel failure and proposed Gemini-as-prompt-owner before spending time on a Gemini-authored page.
2. **The input channel claimed success without grounding.** Cursor K3 explicitly said all three PNGs loaded, yet it described a completely unrelated crypto product. The objective headline/section probe was therefore essential. Trusting tool narration instead of comparing source identity would have produced an even more misleading result.
3. **Mechanical evidence was broader than visual evidence.** Build success, zero horizontal overflow, and clean console output proved that the pages ran. They did not prove resemblance, taste, or product fit. I kept those scopes separate in the final reports, but the workflow still spent too much time collecting evidence for candidates that Mahiro rejected immediately on visual grounds. A faster first-section gate would reduce that waste next time.

## Lessons Learned

- Visual-owner identity is part of the experiment contract; a model substitution changes the hypothesis even if the skill itself is model-agnostic.
- A model claiming that images loaded is not evidence of visual grounding. Require an objective blind identity probe before writes.
- Gemini-authored prompt → K3 can be an explicitly approved fallback route, but it is not equivalent to K3 directly understanding the pixels.
- Build, overflow, console, hash, and role receipts are technical evidence only. Mahiro's human visual verdict remains authoritative.
- Start with one bounded hero/section candidate when testing a new visual route; do not build a full page before the ownership and taste path has earned confidence.
- Rejected experiment artifacts should remain until the human explicitly asks to delete them, then be removed narrowly while preserving unrelated work.
- Avoid unbounded `networkidle` waits against HMR dev servers; use explicit readiness plus bounded image loading for capture.
