## AI Diary

## Honest Feedback

มี friction สามจุดที่ควรจำ จุดแรกคือคำตอบก่อนหน้านี้บอกว่าไม่ต้องแก้ตัว subagent เพราะ fallback อยู่ที่ Main ซึ่งถูกต้องสำหรับ requirement ตอนนั้น แต่พอ requirement เปลี่ยนเป็น “แทน Spark ไปเลย” ผมต้องทิ้ง reasoning เดิมทันที ไม่ควรยึดกับคำอธิบายเก่าเพียงเพราะเพิ่งเขียนลง memory จุดที่สองคือผมลองใช้ `ApplyPatch` กับ global agent definition ทั้งที่ cross-agent memory guard มองพื้นที่นี้เป็น guarded scope แม้ Mahiro อนุญาตชัดเจน การลองนั้นไม่ทำให้ข้อมูลเสียหาย แต่เพิ่มหนึ่งรอบที่หลีกเลี่ยงได้ ถ้าจำ boundary ของ tooling ได้แม่นกว่านี้ จุดสุดท้ายคือ model metadata ของ Agent tool ใน conversation ปัจจุบันอาจยังแสดง Spark เพราะ registry ถูกสร้างตอน process start การตรวจไฟล์อย่างเดียวจึงพิสูจน์ persisted configuration แต่ไม่พิสูจน์ว่า process เก่ารับค่าใหม่แล้ว รายงานต้องแยกสองเรื่องนี้เสมอ และไม่ควรรับประกันว่า `/reload` เพียงอย่างเดียวจะพอในทุกเวอร์ชัน

## Lessons Learned

- ถ้าจะเปลี่ยน default model ของ custom subagent จริง ต้องแก้ทั้ง frontmatter และ Main routing memory
- Explicit `model:` ใน Agent call มี priority สูง จึงต้องอัปเดตพร้อม definition ไม่อย่างนั้นสองชั้นจะขัดกัน
- Fallback policy กับ default replacement เป็นคนละ contract เมื่อ Mahiro บอกว่า “แทนไปเลย” ต้องลบ route เก่า ไม่ใช่ซ่อนไว้เป็น fallback ต่อ
- หลังแก้ global custom-agent definition ให้แยก persisted-file verification ออกจาก active-process verification
- ถ้า patch tool ถูก guard ปฏิเสธ ให้ใช้การเขียนแบบ bounded ที่ตรวจ old value และ readback แทนการเขียนทับทั้งไฟล์
- งาน commit ยังต้องใช้ specialized safety procedure เดิม การเปลี่ยน model ไม่ได้เปลี่ยนสิทธิ์ในการ commit, amend หรือ push
