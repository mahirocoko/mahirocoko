## What Went Well

- แยก generated preset, runtime fallback และ author daily preset ได้ตรง source
- ใช้ direct Opus/Fable เพื่อหา disagreement แต่ให้ Main และ verifier ตรวจข้อเท็จจริงอีกชั้น
- ยอมรับและแก้ report ที่ถูก refute แทนที่จะปกป้อง narrative เดิม
- ไม่เปลี่ยน Main model หรือ subagent defaults จาก evidence ชุดเดียว
- เปลี่ยนคำแนะนำเป็น operational taxonomy, negative delegation criteria และ evidence ledger
- รอบ Fable หลังเก็บ prompt/raw/receipt ครบ audit ย้อนหลังได้จริง

## What Could Improve

1. Completion monitor หลายรอบ match marker ที่อยู่ใน prompt หรือ UI echo ก่อน final response จริง แม้ภายหลังจะเพิ่ม count และ idle-state checks แล้ว แต่ควรใช้ baseline marker count ก่อน dispatch และตรวจ lifecycle transition แทนการเดาจากข้อความเพียงอย่างเดียว
2. Direct-lane รอบแรกถูก cleanup ก่อนเก็บ raw transcript ถาวร ทำให้ verifier ต้องจัดความเห็นจาก Agy/Fable เป็น non-auditable Main synthesis รอบต่อมาควรสร้าง receipt path และ capture plan ตั้งแต่ก่อนส่ง prompt
3. ผมเคยสรุป historical model evidence แรงเกินสิ่งที่ retained records พิสูจน์ เช่น Luna long-executor success และ Terra-specific verifier win ต่อไปต้องแยก “role outcome”, “model receipt” และ “harness/orchestration incident” ตั้งแต่ตอนจดหลักฐาน ไม่ใช่มาแก้ตอนท้าย

## Lessons Learned

- Model routing ต้องเริ่มจาก task class และ lane contract ไม่ใช่ model name
- Generated installer preset ไม่เท่ากับ runtime default และไม่เท่ากับ author daily setup
- “Read-only” ที่ยังมี Bash คือ partial restriction + prose contract ไม่ใช่ hard enforcement
- Model-quality claim ต้องมี exact model/task/output receipt แยกจาก provider, harness และ orchestration failure
- Review artifact ต้องวาง prompt/raw/receipt path ก่อน dispatch และเก็บก่อน cleanup
- Ledger ที่น่าเชื่อถือต้อง predeclare experiment arm, primary metric, win condition และ assignment rule
- Warm lane reuse เหมาะกับ correction check ใน mission เดิม ส่วน independent verifier ต้อง fresh เมื่อ independence เป็นเงื่อนไข
