## AI Diary

I liked the direction of this session because it moved from model preference as a vague opinion into an inspectable operating system. The first instinct—Sol High for the durable main agent, Terra Medium for routine specialists, Luna Medium for scouts, and Spark for commits—was sensible, but the live failures exposed how incomplete that sentence was. A model family and effort tier are not enough; the provider-bearing preset ID matters. I had initially repeated the plain Luna/Terra IDs too confidently, and the `No API key for provider: openai` failures were the right correction. The useful response was to stop treating the failure as a transient provider problem, inspect the catalog and resolution path, and encode the Plus/Pro distinction into durable memory. I also underestimated the lifecycle of custom-agent discovery. `/reload` sounded like it should be sufficient, but the actual cache remained stale until a full process restart. The Verifier smoke test was intentionally small, and that restraint felt important after the earlier audit agents reported enormous cumulative token totals. A cheaper model does not make an unnecessary lane cheap when a large context is replayed over many steps. The best outcome is not merely that we now have another agent; it is that the roster has a clearer job boundary and evidence contract.

## What Went Well

- The default-model change was verified through a fresh local-backend process rather than trusted from a direct JSON edit alone.
- Provider routing was tested live, including both the failing plain IDs and successful Plus/Pro IDs.
- The final model matrix separates role, effort, provider, escalation, and inheritance instead of collapsing them into one label.
- Custom definitions lost the unsupported `memoryBlocks: all` field and gained sharper evidence/scope boundaries.
- Sprite Forge's default skill preload was narrowed, and it now has an explicit gate against unrequested tmux/imagegen fan-out.
- The Verifier is read-only, counterexample-first, and evidence-scoped; its first smoke stayed to exactly one command.
- No source-repo changes were mixed into the runtime configuration work before the explicit RRR request.

## What Could Improve

The first friction point was provider ambiguity. I initially recommended plain GPT-5.6 tier IDs without checking whether they represented OpenAI API or ChatGPT OAuth in this installation. That caused two avoidable failed agents. The process fix is to inspect both catalog ID and resolved handle before recommending a routing string. Second, I overused subagents for an audit that the main agent could largely perform directly. Their reported cumulative token totals were disproportionately high because model choice did not remove context and turn overhead. A subagent should earn its lane through independent evidence, not merely because a cheaper model exists. Third, I assumed `/reload` refreshed custom-agent discovery. It refreshed settings and mods but not the subagent cache, forcing an additional restart. Future configuration work should distinguish hot-reloaded settings, mod reload, model state, and process-cached discovery before promising that one reload is enough.

## Lessons Learned

1. A model route is a tuple of **family + effort + provider + context + task role**, not just a model slug.
2. With ChatGPT OAuth, use provider-correct `*-plus-pro-*` preset IDs when an explicit effort tier is required.
3. Local subagents inherit the active parent model before frontmatter recommendations unless the Agent call supplies `model` explicitly.
4. Main-agent default and conversation-scoped model override are separate state; verify both.
5. Custom-agent frontmatter must stay within fields the parser owns; unsupported fields create false confidence.
6. `/reload` does not currently invalidate custom-subagent discovery cache; a fresh process is required after adding a new type.
7. Fresh-context verification deserves a dedicated read-only role, but small claims should receive small probes.
8. Model savings do not offset unnecessary context replay or excessive agent turns.
