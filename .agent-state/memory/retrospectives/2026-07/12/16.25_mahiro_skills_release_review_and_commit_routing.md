## AI Diary

I felt productive in this session, but the most important lesson came from a small orchestration mistake rather than the large release work. The sprite and frontend-design changes received unusually strong verification: real fixtures, multiple fresh reviewers, package installs, provenance checks, release alignment, and global receipt updates. Yet I still missed a simple requirement in my own Agent call. I selected the specialized `git-commit` subagent and assumed its configured or recommended model would be honored automatically. The calls worked, so the mistake was easy to overlook. Mahiro's repeated question exposed the real issue: it was not whether Spark was capable; I simply had not passed the model explicitly. Worse, my earlier Context Doctor cleanup had weakened a precise rule into vague shorthand. That is a useful warning about compression: removing a concrete invocation example can remove behavior, even when the summary appears semantically equivalent. I am glad we traced the exact cause instead of rationalizing it as a model limitation. I also appreciated the deliberate frontend-design review loop. Codex App produced a thoughtful research workflow, but review still mattered because self-consistency, approval state, provenance, and compatibility aliases are easy to miss in a large prose-heavy diff. The session ended with cleaner skills and a clearer rule for how I should route future commit work.

## Honest Feedback

Three friction points stand out. First, prose-heavy skills can pass many string-based tests while still carrying state-machine contradictions. Tests should protect transitions and ownership boundaries, not only phrases. The final comparison tests improved this substantially. Second, release work becomes risky when approval state is implicit. The Macapp study initially described findings as promoted even though its own new contract required explicit maintainer approval. Recording candidate IDs, bounded scope, evidence, counterexamples, and Mahiro's approval made the release honest. Third, configuration metadata and actual invocation are different layers. A subagent type can recommend Spark, and a local agent file can name Spark, but the parent still needs to pass the model explicitly when the tool API does not guarantee selection. Future commit runs must inspect the exact Agent payload, not infer behavior from successful completion. These are not abstract process preferences; each one prevented a plausible release or coordination error in this session.

## Lessons Learned

- Preserve exact operational examples during memory compaction when behavior depends on a tool parameter.
- Model metadata is not a substitute for an explicit routing argument.
- Use approval ledgers when research findings cross from evidence into durable skill doctrine.
- Separate machine-verifiable evidence from visual judgment instead of pretending one validator owns both.
- Test package/default-bundle boundaries explicitly, especially when one related skill must remain optional.
- A release is complete only when source, tests, provenance, remote/tag/release state, and installed receipts agree.
