## Architecture Decisions

- Runtime capability belongs in a computer-scoped Mod; workflow prose should not become another always-visible Skill.
- Keep one cohesive unified model tool to limit Letta registry pressure while preserving natural-language bookmarking across conversations.
- Natural-language bookmark routing is two-stage: expose the real collection tree, then save only with an explicit chosen collection ID.
- Treat Raindrop suggestion as optional because the live account proved it is Pro-only.
- Recollection is snapshot → classification → explicit hierarchy contract → immutable plan → human review → exact apply.
- Mutations become `unknown` before dispatch and are reconciled from fresh remote state; ambiguous writes are never blindly retried.
- Whole-library moves use the documented bulk endpoint in batches of at most 50 IDs after complete stale-state preflight.
- Delete is not a permanent Mod capability. Legacy collection removal was a one-off, exact, preflighted cleanup with private receipts.

## Honest Feedback

Three friction points stand out. First, the original Mod became too large too quickly, and the first implementation agent consumed excessive time and context before basic endpoint parity was independently checked. A smaller authenticated-read milestone should have preceded recollection and bulk migration code. Second, the OAuth debugging loop asked Mahiro to retry several times because the error response was initially over-sanitized. Safe diagnostics should expose bounded provider `errorMessage` fields from the beginning, while never exposing credentials. Third, the taxonomy process created a verbal hierarchy before creating its machine-verifiable contract. That gap led to a justified verifier rejection and an extra review cycle. For future migrations, the hierarchy, allowed leaves, and source-to-target mapping should be one versioned artifact before classification begins. The reload warning also consumed avoidable effort; known host registration pressure should have guided the Mod toward one unified tool from the start. None of these issues caused data loss, but each increased latency and made Mahiro repeat foreground actions more than necessary.

## Lessons Learned

- A complete-library claim requires a count-backed, non-truncated snapshot; a configured limit is not evidence of completeness.
- External API documentation establishes method/body contracts, but plan tiers and live response shapes still need safe runtime probes.
- For large migrations, classify into an explicit allowlisted hierarchy artifact before constructing operations.
- Persist unknown-before-dispatch and reconcile after mutation; transport success/failure alone is not a reliable postcondition.
- Consolidating cohesive Mod tools reduces Letta reload pressure without requiring command-only degradation.
- Human authorization for an exact cleanup can support a one-off destructive action without creating a permanent destructive capability.
- Verify data preservation after deletion, not just before it.
