## AI Diary

I protected against reuse by subtracting too much: abstract substitutes, less material fidelity, and an incomplete asset story. Mahiro's correction was precise and useful. ## Honest Feedback

1. **I overcorrected for IP risk.** The first implementation confused “do not copy source pixels” with “do not recreate the complete visible asset system.” That produced an assetless approximation and forced Mahiro to restate the desired fidelity boundary. The better default is role-preserving replacement: map every visible role, then decide Keep/Adapt/Generate/Reject per role.
2. **I initially judged visual progress before interaction ownership was complete.** Action/Writing autoplay and the field-note marquee looked closer to the reference, but they lacked explicit pause behavior. Reduced motion alone was not enough. Moving content needs ordinary user control, and screen-reader announcement ownership must be deliberate.
3. **The tooling interface still added avoidable friction.** Shelling out to `qa-command.mjs` required JSON quoting, tab-ID bookkeeping, and manual lifecycle cleanup. One selector payload failed because of quoting; an old controlled-tab ID also became stale. The bridge itself was highly valuable, but its command surface should be typed and lifecycle-aware so agents spend less attention on transport ceremony.

## Lessons Learned

- Reference fidelity is a combination of anatomy, material, timing, state choreography, and user control—not section order alone.
- Source/IP safety should preserve product roles while replacing identity and pixels with original assets.
- Product screenshots should come from the real semantic runtime whenever text/UI accuracy matters; imagegen should supply visual/media roles, not fake interface text.
- HiroHiro is strongest for real-Chrome reference inspection, computed CSS, exact section captures, timed states, and trusted postconditions.
- Playwright remains the better complement for viewport matrices, reduced-motion emulation, network/console checks, and deterministic geometry assertions.
- Trusted click capability must remain explicit and capability-gated; ordinary synthetic input should be tried first and postconditions must always be checked.
- Screenshot filenames and reports are contracts. Capture the state, verify its text, then name it.
- A whole-page review can find layout/interaction failures that narrow checks and passing tests miss.

## Should HiroHiro become MCP?

Yes—but as a **thin adapter**, not as a rewrite or a second source of truth.

Recommended architecture:

1. Keep the extension + local QA bridge + control protocol as HiroHiro's core.
2. Add a local stdio MCP adapter that wraps the existing typed QA commands and forwards to the bridge.
3. Preserve the CLI for humans, scripts, CI diagnostics, and clients without MCP.
4. Keep a dedicated HiroHiro skill for workflow, safety policy, evidence sequencing, and when to use trusted input; MCP supplies tools, not judgment.
5. Expose capability tiers:
   - read-only: list tabs, inspect elements/text/CSS, capture section/screenshot
   - ordinary interaction: scroll, hover, synthetic click/fill
   - trusted debugger input: explicit opt-in, controlled-tab-only, postcondition required
6. Preserve current safety contracts: localhost/token boundary, one controlled tab, operation lock, circuit breaker, command IDs/timestamps, automatic clear/release, and no arbitrary browser eval by default.
7. Make tab identity and lifecycle first-class resources so stale IDs are detected and recoverable.

MCP would materially help because the work repeatedly needed structured tool calls, schema discovery, and consistent result objects. It would eliminate shell quoting and reduce manual parsing. It would not improve screenshot quality by itself; that value already comes from HiroHiro's extension/bridge. The ideal shape is **core protocol + CLI adapter + MCP adapter + workflow skill**.
