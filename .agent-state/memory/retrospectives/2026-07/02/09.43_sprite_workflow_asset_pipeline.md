## Architecture Decisions

- Treat sprite work as a pipeline, not a prompt. The correct sequence is source candidate → deterministic extraction → QA previews → QA gates → center/sliver fixes → human visual review → promotion.
- Do not swap candidates just to fix one feature. A candidate with better tail but worse silhouette/motion should not replace a better-motion winner; fix extraction or regenerate under the same contract.
- Chroma-key color selection matters. Magenta works for white cats, but effects like sakura petals are pink and therefore conflict with magenta thresholds. Future effect prompts may need an alternate key color or separate effect layer.
- QA metrics are necessary but not sufficient. The sword-sakura candidate passed important checks, but Mahiro’s visual judgment was correct: it did not look good enough. Human taste remains a hard gate.

## Honest Feedback

The biggest friction point was that I moved too quickly from “candidate exists” to “promote draft.” I did inspect previews, but I still let mechanical QA have too much authority over the sword-sakura result. The second friction point was candidate reasoning: for the kneel output, I briefly optimized for tail completeness at the cost of motion quality, which is exactly the kind of local optimum that an asset pipeline is supposed to prevent. The third friction point was release/update scope: when updating skills with `guided --mode update --yes`, the command updated every receipt-backed global agent, not just Letta Code. That was explainable but still broader than the immediate intent. Future work should either add an update filter or use more precise commands when only one agent’s installed skills need refresh. Overall, the session produced valuable tooling, but it also showed that tooling must stay subordinate to visual taste and explicit asset contracts.

## Lessons Learned

- Sprite extraction should preserve the chosen motion candidate and adjust crop/alpha/center, not replace the candidate unless the whole candidate is worse.
- QA gates need to cover both machine-checkable issues and visual-review gates. Center/sliver/tail checks are good, but not sufficient for animation appeal.
- Effects that share hue with chroma keys need special handling. Sakura petals plus magenta background creates a threshold conflict.
- For Codex CLI, check `codex exec --help` specifically before using flags remembered from global `codex --help`.
- Mediocre generated assets should be deleted cleanly rather than committed as “drafts” if they are not useful.
