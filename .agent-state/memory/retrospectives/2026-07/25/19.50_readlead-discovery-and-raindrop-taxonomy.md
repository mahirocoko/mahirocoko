## AI Diary
I handled the ReadLead work well once I stopped treating it as a frontend-only mockup. The reference image made the reader surface easy to imagine, but the product risk actually lives behind it: source extraction is imperfect, translation quality needs persistent context, and token cost becomes a product decision rather than a hidden infrastructure bill. Writing the client proposal was useful because it forced the promising but vague brief into acceptance criteria, exclusions, and a staged delivery path. I made one clear mistake when Mahiro asked to “put it into a category.” I moved the ReadLead documents into a docs category even though the active context was the newly added Raindrop bookmark. The correction was quick, but the lesson is that a noun like “category” must be resolved against the immediately preceding object, not the last thing I edited. The Raindrop flow then showed why the gated planning model is useful: I could inspect the current taxonomy, identify the bookmark and parent collection, create a precise one-create/one-move plan, and leave the irreversible mutation to Mahiro’s explicit apply step.

## Honest Feedback
The first friction point was assumption momentum. I had just organized ReadLead files and therefore projected that meaning onto Mahiro’s request, even though the system reminder had named the Raindrop `canvas-ui` bookmark. A short recognition check would have prevented the detour. The second was tool-surface uncertainty: the duplicate bookmark response did not include a collection tree, and I initially stopped too early instead of using the available snapshot/plan route described by memory. I recovered once I checked the durable Raindrop contract, but I should lead with the strongest available safe workflow rather than asking the user for an ID prematurely. Third, the ReadLead documents grew quickly across several files. They are useful now, but future additions should avoid repeating the same architecture explanation; the proposal should stay client-facing while the technical scope retains implementation detail.

## Lessons Learned
- Treat URL extraction, segment identity, glossary ownership, and cost settlement as first-class product contracts for AI reading tools.
- Ask clients a small set of decision questions before presenting provider/model choices as settled architecture.
- When a bookmark is already a duplicate, use a sanitized snapshot and proposal plan to recover collection context rather than guessing a destination.
- Resolve ambiguous references against the latest user action before reorganizing files or state.
