## AI Diary

The most important correction was conceptual. I initially reached for a generic “convert MCP to skill” workflow even though Mahiro already had a deliberate MCP Proxy architecture. Mahiro stopped that drift immediately. Once I returned to the actual system, the design became much clearer: Browser Control already owned protocol validation, private session loading, explicit controlled-tab state, screenshots, and domain adapters. MCP only needed to become a thin structured invocation façade. I also changed my mind about `list_tabs`. It sounded read-only, but an independent audit correctly pointed out that full titles and URLs from unrelated tabs can contain sensitive query strings or fragments. Removing the action was better than inventing a partial redaction policy without a real use case. The URL-prefix issue was even more valuable: a target assertion described as a safety boundary must not accept lookalike origins. Native proof after Mahiro reloaded and claimed a tab made the contract tangible—status, page state, bounded text, and screenshot all worked, while malicious-origin and partial-path assertions failed closed. The session reinforced that a capability layer earns trust through narrow ownership and disconfirming tests, not by exposing every command that happens to exist.

## Honest Feedback

1. **I selected the wrong workflow at first.** Mentioning MCP should not automatically route to a conversion skill when a project-specific proxy already exists. I should have inspected the cached proxy inventory and project memory first.
2. **My first MCP proposal was too broad.** Including `list_tabs` treated “read-only” as equivalent to “privacy-safe.” The audit showed that observational tools can still leak unrelated authenticated context.
3. **I trusted an old URL assertion too quickly.** Requiring `targetUrl` in MCP looked safe, but the extension implemented it with raw `startsWith`. A new façade must audit every inherited safety claim it relies on, not merely add validation at the edge.

The recovery was strong: both medium findings were fixed rather than documented away, tests were added at protocol/tool levels, the extension was rebuilt/reloaded, and native hostile-target checks proved the correction. The result stayed compact—one tool, no mutation surface—despite the temptation to mirror the full CLI.

## Lessons Learned

- MCP is useful only when it provides machine-readable discovery **and** structured invocation. If it only tells the agent which CLI command exists, a skill/doc is enough.
- MCP adapters should wrap the existing capability owner; they must not duplicate browser, product, or approval logic.
- “Read-only” does not imply privacy-safe or side-effect-free. Tab lists, screenshots, focus changes, and local artifacts need explicit treatment.
- A safety façade must audit inherited boundaries such as URL matching, session loading, and error redaction.
- Prefer one compact allow-listed tool through MCP Proxy over dumping every protocol command into context.
- Keep consequential action approval outside a generic read adapter even when the underlying protocol supports it.
