## Key Code Changes

- `mcp_proxy` now stays read-only and handles cached metadata operations only.
- `mcp_proxy_live` handles live `reconnect`, `call`, and `disconnect` with approval gating.
- Persistent stdio connection pool reuses running processes until reload/disconnect/process exit/config hash change.
- HTTP/SSE support is SDK-backed with `StreamableHTTPClientTransport` and `SSEClientTransport`.
- Config discovery now loads global config first, then project overrides.
- Cache stores metadata only, not command/args or token plaintext.

## Architecture Decisions

The most important decision was to keep the proxy lazy and compact rather than registering all MCP tools directly into context. The second important decision was to package the mod before adding HTTP/SSE. That gave the mod a controlled dependency boundary for `@modelcontextprotocol/sdk`, which is necessary because HTTP/SSE MCP has enough session/header/message-endpoint complexity that hand-rolled transport code would be a maintenance trap. Finally, global config became the right default once MCP moved from repo experiment to durable agent capability, while project configs remain useful as overrides.

## What Went Well

- Dogfood found real issues quickly: approval behavior, verbose output, and config locality.
- The lazy proxy pattern stayed intact while gaining practical power.
- Validation was evidence-based: mock harnesses, real WebClaw/example.com calls, synthetic collision fixtures, persistent PID/counter fixtures, HTTP/SSE SDK fixtures, and installed-package runtime checks.
- Packaging gave us a path to dependencies without relying on brittle global imports.

## What Could Improve

- I initially patched the live action approval too optimistically and only noticed the problem after dogfooding. In future mod work, anything that starts processes or calls external tools should have a tool-level safety boundary from the start.
- Local package install behavior was surprising: `letta install <local dir>` did not copy/install dependencies automatically. I had to discover and patch around that by installing SDK dependencies into the installed package root. Future package work should check dependency presence immediately after install.
- The package setup is now functional but still local/manual. If this mod becomes long-lived, it should probably move into a small repo or canonical package source instead of living only under `~/.letta/mcp-proxy/`.

## Blockers & Resolutions

- **Approval overlay not reliable enough**: split `mcp_proxy` and `mcp_proxy_live`.
- **HTTP/SSE complexity**: used the official MCP SDK transports instead of hand-rolling.
- **Local package dependency gap**: installed `@modelcontextprotocol/sdk` into the installed package root and documented the recovery command.
- **Global config duplicate detection**: fixed the config walker so `~/.letta/mcp.json` is not counted twice as both global and project config.

## Honest Feedback

The biggest friction point was that I let the single-file prototype grow quite far before switching to a package. It worked, but the transition cost showed up once HTTP/SSE required dependencies. A cleaner approach would have been to package immediately after v0.2 stabilized, before adding persistent connections and transport support. Second, I had to correct my own confidence around approval behavior. Mock validation was necessary but insufficient; live dogfood exposed a gap that tests did not. Third, I accumulated many local/external changes outside the repo, which makes commit and handoff less straightforward. That is acceptable for trusted Letta mod infrastructure, but it means I need crisp notes and backups, otherwise future me will struggle to reconstruct what lives in repo history versus local runtime state. The session succeeded, but it also proved that local agent infrastructure needs a stronger release discipline once it becomes durable.

## Lessons Learned

- Split read-only and live tools early when building proxy capabilities.
- Do not hand-roll HTTP/SSE MCP; use SDK transports and test streamable, SSE, auto fallback, headers, and bearer auth explicitly.
- Local Letta mod packages with dependencies need a post-install dependency presence check.
- Global MCP config is the right default for agent-level capabilities, but project override precedence must avoid double-counting the global file.

## Next Steps

1. Use the packaged MCP proxy in ordinary work before adding more features.
2. If needed, add an explicit package update script that reinstalls dependencies and reloads cleanly.
3. Consider moving `mahiro-mcp-proxy` into a small source-controlled repo/package if it keeps growing.
4. Defer OAuth, direct MCP tool registration, and persistent HTTP session reuse until there is a concrete need.
