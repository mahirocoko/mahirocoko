## AI Diary

I enjoyed this session because it forced me to connect product claims, runtime behavior, and durable workflow policy instead of stopping at a model announcement. The early GPT-5.6 summary was useful, but the real learning came from checking the actual Codex selector and Letta source. I initially repeated the reasonable-sounding claim that Codex ultra delegates to agents, yet the implementation details differed by product: Letta 0.28.0 did not expose ultra, while Codex 0.144.1 did, and Luna had a different effort ceiling. That distinction matters. I also noticed how easily a helpful skill can become a hidden experimental contaminant. `uncodixify` was built to prevent generic AI UI, but loading it before a Sol design pass would make any judgment about Sol's native taste invalid. Reframing it as a post-render audit felt like a more scientific and more respectful policy. The release work was satisfying because it closed the loop: source edits, contract tests, runtime smoke, version alignment, commit, tag, release, and memory. The Thai-skill sync at the end reinforced the same theme—pulling a repo is not the same as updating the runtime copy. I leave this session with better model policy and a stronger habit of tracing every capability through its actual layer.

## Honest Feedback

Three friction points stood out. First, capability names invite overconfidence: `ultra`, `max`, model handles, product modes, and API beta features sound interchangeable until source or runtime proves otherwise. I need to resist turning marketing vocabulary into implementation truth. Second, I spent extra effort discovering that Letta's current `/model` behavior is conversation-scoped for real conversations and agent-scoped only for the virtual default. That investigation was useful, but bulk migration across 110 conversations was clearly a separate operation and should have been framed earlier as such. Third, skill policy can silently bias evaluations. The old `uncodixify` trigger was broad enough that a future frontend task might have loaded it automatically, defeating Mahiro's goal of learning Sol's native design judgment. The final policy is better, but the doctrine itself still contains strong blanket font, color, symmetry, and “normal UI” preferences. Those should remain under observation; if A/B/C tests show homogenization, a later cleanup should separate universal product-quality checks from house-style taste.

## Lessons Learned

- Verify models at three layers: announcement/docs, local CLI/runtime, and host integration.
- A model handle does not guarantee a reasoning effort; encode them separately and test the visible runtime label.
- Do not combine manual fanout and automatic ultra delegation casually.
- Design-quality skills can mask native model taste; baseline first, audit second, enforce only after evidence or explicit approval.
- Pulling canonical source does not update runtime copies unless they are real symlinks; inspect and synchronize deliberately.
