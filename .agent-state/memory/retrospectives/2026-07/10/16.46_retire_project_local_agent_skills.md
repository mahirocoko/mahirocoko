## AI Diary

This session made me confront how easily useful experimentation becomes accidental infrastructure. The project-local `.agents` tree had grown into a dense bundle of frontend design prompts, brand generators, style presets, image workflows, and scripts. Many of those files represented thoughtful work, and deleting them initially felt risky because removal can look like losing capability. The better interpretation emerged only after the comparison: the capability was not the files themselves. The durable capability was the role split and workflow knowledge we could preserve in the canonical skill system. I was especially glad Mahiro stopped the first release path when `frontend-design` did not appear after an all-agent install. My initial optional-bundle decision was logically consistent with clean native-model experiments, but operationally inconsistent with Mahiro's meaning of a core skill. The correction was better: install it everywhere as a primary skill, then rely on precise trigger metadata and workflow boundaries to avoid auto-conditioning native Sol tests. Returning to this repo and finding active lab READMEs that still pointed to deleted compose scripts was another useful check. A deletion is not complete when the folder is gone; the active guidance must also stop promising the old runtime.

## What Went Well

- The cleanup was deliberate and historically recoverable through Git rather than an untracked destructive wipe.
- Taste Skill was studied before deletion, so useful planning/reference contracts were extracted instead of discarded blindly.
- Canonical `frontend-design` received fresh-context review, contract tests, official packaging validation, and real adapter-install verification.
- Mahiro's install-all correction was caught before tag/release publication, then encoded as a regression test.
- Current design-prompt entrypoints were checked after deletion instead of assuming tracked path removal was sufficient.

## What Could Improve

- The first proposed canonical skill state kept `frontend-design` outside the default bundle. That protected native baselines but violated the expected meaning of “install all.” Trigger policy should have been the first protection mechanism, not absence from installation.
- I initially validated explicit plans and package structure before running a true default all-agent install. The real install test should have happened before the first release commit.
- The old project-local skill tree was large enough that a role/inventory map should have been written before deletion, even though Git history preserves every file. We reconstructed the major owners from status and prior study, but a compact manifest would have made the handoff even clearer.

## Honest Feedback

Three friction points deserve emphasis. First, “optional” and “core but explicit-triggered” are not the same product concept. I conflated them because both can protect experiments, but they create very different install expectations. Mahiro was right to choose one clear default bundle and defer future refinement. Second, tests can provide false comfort when they prove only explicit-item planning. The strongest evidence came from installing the default bundle into isolated global and local roots, listing receipts, and checking actual `SKILL.md`/command files for every adapter. That pattern should become the standard for new core skills. Third, cleanup work needs a live-reference pass. Historical docs should remain untouched, but current README entrypoints must not advertise commands under a deleted runtime path. I caught four such files only after a broad exact search. In future removals, the checklist should explicitly distinguish current guidance, historical records, generated artifacts, and canonical replacements.

## Lessons Learned

- One durable canonical skill owner is clearer than a project-local mirror plus a shared bundle.
- Core skill installation and native-model evaluation should be controlled independently: install by default, trigger explicitly.
- Verify default/all behavior with actual isolated installs and file checks, not only planner output.
- After deleting a runtime tree, update active entrypoint docs while preserving historical records as history.
- Git history is the backup for tracked skill experiments; do not keep stale active copies merely because they contain valuable past work.
