## Key Code Changes

The custom statusline now treats `reasoningEffort` as runtime context, not merely a UI-setting feature flag. It reads multiple paths including `context.model.reasoningEffort`, `context.model.reasoning_effort`, raw model payloads, `model_settings.reasoning`, and `llm_config.reasoning_effort`.

Git status moved from a single dirty count to parsed `git status --porcelain=v2 --branch`, allowing branch, ahead/behind, untracked, modified, and deleted counts. MemFS status now returns a structured object rather than a string so the display can show a precise dirty count.

LLM/tool events are now summarized as short-lived statusline activity with timers. Render remains synchronous; async work still happens through event handlers, polling, and closure state, which matches the statusline mod constraints.

## Architecture Decisions

We did not install `@letta-ai/git-status` or `@letta-ai/conversation-summary` because both are statusline/panel mods that would duplicate or compete with our order-0 custom statusline. The better direction was to borrow their ideas and patch our single owner file.

We also kept Control Room separate. The statusline does not duplicate the whole Control Room cockpit because that would make the primary row too dense. Control Room remains its own panel/trust surface; statusline stays a compact workspace and runtime signal.

## Honest Feedback

Three friction points were real. First, because `~/.letta/mods/statusline.tsx` is global and not tracked by the current repo, it is easy to make a useful change that later becomes invisible to version history. I mitigated that with a backup and RRR, but that is weaker than having a canonical source file. Second, the statusline is getting powerful enough that it may drift into a mini-dashboard. Mahiro's taste generally favors compact, practical signals; if the row starts showing too many segments, we should prune rather than keep adding. Third, Control Room reminders during these small workflow tweaks can be helpful but also noisy. I updated it when implementation state changed, but for conceptual exploration the right move remains to continue normally unless there is a real goal/progress change.

## Lessons Learned

- For Letta Code panel/statusline work, `context.model.reasoningEffort` is the right runtime truth for reasoning display; do not gate reasoning display solely on `reasoningTabCycleEnabled`.
- Custom order-0 statusline should usually absorb useful ideas from package mods rather than install competing order-0 panels.
- Keep render synchronous and side-effect-free; use event handlers/timers/async polling to update closure state, then `panel.update()`.
- External global mods need explicit backups and session documentation because repo commits may not include the actual changed file.
