## Architecture Decisions

The important decision was not to reinstall the old `goal-mode` immediately. Even though `@letta-ai/goal-mode` exists, the better direction for Mahiro's main agent is `control-room + plan-mode + threadkeeper` because it separates goal, verification, and live operational state more cleanly than the old built-in goal loop. `goal-mode` can stay as a compatibility option, but should not be the first replacement.

Another decision was to treat powerful mods such as `muscle-memory`, `autopivot`, `hypa`, and `output-compressor` as later experiments, not global defaults. They are interesting, but each can alter core agent behavior deeply. The Core Practical set is safer because it mostly improves visibility, planning, and context hygiene without silently changing commands/models/output.

## Lessons Learned

- Letta Code `v0.27.21` removes built-in goal mode/tools; do not call `CreateGoal`, `UpdateGoal`, or `GetGoal` in future sessions.
- For Mahiro's workflow, the practical replacement is layered: `control-room` for long-running goal/progress/verification, `plan-mode` for approval-gated planning, and `threadkeeper` for temporary live constraints.
- Installed mods can improve continuity, but they can also create noise. Use them by responsibility boundary, not habit.
- `/mods` slash command now belongs to mod-learning; use shell `letta mods list` for installed mod management.
