## AI Diary

I began this work with the right instinct—measure before replacing infrastructure—but the session reminded me how quickly a seemingly simple model switch can cross several ownership boundaries. I was pleased that the benchmark did not become a vanity scorecard: the verifier forced me to strengthen relevance labels, retain provenance, and distinguish Qwen query instruction from a nonexistent vector “decoder.” The strongest moment was not Qwen winning; it was recognizing that the benchmark result justified only a model migration, not a new retrieval stack, larger model, or reranker.

I also made a readiness mistake. I initially treated focused tests and a self-consistent helper patch as enough, then the independent verifier found two real fail-closed gaps: contradictory Git status/output could still narrow scope, and final rehashing reused the old candidate tuple. That correction was valuable because it changed implementation rather than merely wording. I felt the tension between momentum and security ceremony throughout the Eizypay rebuild. The right resolution was to keep the gate strict, diagnose the exact allowlist relationship, and remove only stale metadata instead of bypassing the hook. By the end, every heavy process was serialized, Qwen was unloaded, and the runtime state matched the claimed outcome. The session was long, but the final system is both faster in retrieval quality and more honest about what remains: direct CCC queries are still raw until a caller-side formatter is implemented.

## Honest Feedback

Three friction points stand out. First, the initial helper patch was too assumption-shaped. I checked normal Git behavior but did not immediately write adversarial status/output combinations or recollect the candidate universe after scanning. A security boundary needs hostile-state tests before a readiness claim, not after a verifier disproves it. Second, I made Mahiro repeat the question “what do I need to do?” because I mixed user actions, agent-owned work, and optional future work in the same updates. The better communication pattern is one explicit line: no action now, then one exact action only when needed. Third, the release boundary became scattered across global settings, installed helpers, ignored project metadata, two Git repositories, and memory. I eventually classified those surfaces correctly, but I should have maintained that ownership map from the start. The positive counterpoint is that I did not bypass the permission hook, did not read the flagged secret-like value, did not overlap heavy index jobs, and did not hide the verifier refutation. Those choices prevented a fast but untrustworthy migration.

## Lessons Learned

- An embedding-model migration is complete only after global config, vector dimension, every existing index, query behavior, and loaded-model cleanup agree.
- Qwen's query-side instruction is a caller contract; changing the document model alone does not make direct `ccc search` instructed.
- Git candidate security must validate exit status and output semantics together, then recollect the complete candidate scope after scanning.
- An exact exclusion can make an existing governed allowlist entry invalid because the allowlisted path is no longer inside the scan scope; preserve unrelated entries and regenerate a bound receipt.
- Full source tests, active installed hashes, live hook reload, and a real guarded index are distinct gates.
