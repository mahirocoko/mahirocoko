## Honest Feedback

1. **The research phase was expensive and initially too broad.** Three agents produced overlapping GPT-6 evidence, and the first comparison mixed Astra, Sol, Luna, and Opus before the taxonomy was corrected. A tighter initial scope—“GPT-6 family only, then Opus separately”—would have reduced duplication.
2. **Runtime configuration boundaries were easy to confuse.** The server helper looked like the documented path, but the local backend had no API key. The local CLI was the correct authority here, yet that distinction only became obvious after a failed attempt. Future self-configuration work should inspect backend mode and use the native command first when the session is local.
3. **Memory and runtime definitions can drift independently.** The routing memory was updated before the `~/.letta/agents/` files, which temporarily created a plan that the actual subagent declarations did not implement. The explicit definition readback fixed it, but the workflow should treat memory, agent definitions, catalog, and first-use runtime identity as four separate evidence layers.

## Lessons Learned

- “GPT-6” needs family-member qualification in all routing and research notes.
- A model catalog entry is availability evidence, not runtime identity or effort proof.
- Main-default migration and subagent-definition migration are separate operations.
- Local Letta model changes should use `letta model set`; server patch helpers require the correct API backend credentials.
- Agy/Gemini remains the primary external lane; GPT-6 changes the fallback roster, not the ownership model.
- The `shadcn-ui/lint` study is useful evidence for repo-local contracts, normalized analysis boundaries, conservative uncertainty handling, and behavior-first quality gates.
