## Honest Feedback

Three friction points stand out. First, I initially treated a successful CLI release build as nearly sufficient packaging evidence. I should have inspected the official package manifest and companion-binary layout before installing anything; that would have prevented the missing code-mode host failure. Second, I launched the first interactive proof with the full existing MCP configuration even though the task needed no MCPs. That exposed Mahiro to repeated Keychain prompts and interrupted the flow. The recovery was safe and no image call was spent, but a startup-only smoke with credential-store isolation should have preceded the paid proof. Third, the verification loop became noisier than necessary: one shell wrapper used the reserved zsh variable `status`, so the focused tests passed but the aggregate command exited 1 after completion and required a clean rerun. The session still finished with strong evidence and no contamination of official Codex, but future private CLI adaptations should start from package anatomy, credential side effects, and one explicit smoke checklist before provider usage.

## Lessons Learned

- A standalone CLI executable may depend on version-matched sibling resources even when version/login probes pass; inspect the official package layout before promoting a custom build.
- macOS Keychain authorization follows executable identity. A custom binary using shared configuration can legitimately trigger new access prompts even when it shares the same auth files.
- For native-alpha claims, require the structured provider input, provider result metadata, real RGBA/channel analysis, and visual inspection together. Prompt wording or a checkerboard preview is insufficient.
- Keep specialized machine-local launchers purpose-specific. `codex-imagegen` owns transparent/no-background output; official `codex` continues to own ordinary generation.
- A failed pre-generation startup is not a spent provider call. Stop, repair the runtime boundary, and preserve the exact one-call proof ceiling.
