## Architecture Decisions

- CCC remains the indexing and vector-storage owner; no replacement retrieval stack was introduced.
- The global default is now raw EmbeddingGemma at 768 dimensions because CCC's Ollama path cannot prepend literal document/query prompts.
- Global model selection and per-project index migration are separate decisions. A model-line change never makes an old vector index compatible.
- Exact identifier lookup remains an exact-search job even when semantic retrieval quality improves.
- Security gates remain fail closed. The pilot used a safe mirror rather than modifying intentional source symlinks or weakening strict scanning.

## AI Diary

I started this work expecting a relatively narrow model comparison, but the most valuable part became separating three different truths that were easy to blur together: direct Ollama embedding quality, what CCC can actually express, and whether a repository-scale index behaves the same way as a curated symbol corpus. The bounded benchmark made EmbeddingGemma look compelling, especially with its code-retrieval prompt, but I did not want to translate that directly into a global recommendation without exercising CCC's real chunking and daemon path. The safe-mirror detour was slower than the ideal path, yet it was the correct response to the symlink and secret-scan gates. I am glad I did not bypass those controls just to get a cleaner benchmark narrative.

The strongest evidence was not one headline metric. It was the convergence of ranking, index time, warm query latency, loaded footprint, and the fact that raw EmbeddingGemma still won even after losing the prompt advantage available in the synthetic harness. I also appreciated Mahiro's instruction to migrate the global setting without rebuilding every project immediately. That forced a clean distinction between default configuration and index readiness. The resulting state is intentionally incomplete but truthful: the new model is selected, while old indexes are explicitly stale. With the weekly pulse showing renewed activity after a quiet local retrospective window, this felt like useful momentum grounded in measured evidence rather than migration enthusiasm.

## What Went Well

- Frozen queries and identical chunk counts made the real A/B comparison understandable.
- Cold index timing started with no Ollama model resident for either arm.
- The source checkout, existing project indexes, and unrelated work remained untouched.
- Cleanup was complete: temporary mirror, index, settings backup, source init artifacts, and loaded models were removed.
- The final migration preserved all global settings except the model line and verified both indexing and query dimensions.

## What Could Improve

- The real pilot query set is still small and path-labeled rather than drawn from a larger organic query history.
- Index-size evidence was not captured before the Qwen reset, so the real pilot compares build time, quality, latency, and residency but not SQLite footprint.
- CCC doctor reports model and existing index status independently but does not clearly declare an old index dimension-incompatible after a global model change.

## Honest Feedback

Three points created avoidable friction. First, the initial attempt to run CCC directly in the source repository reached `ccc init` before the portable helper exposed the tracked-symlink incompatibility. The filename inventory was correct, but the workflow could have identified tracked symlinks earlier and proposed the safe mirror sooner. Second, the local deny policy technically passed strict scanning but did not match the runtime hook's canonical policy invocation. Moving the exact deny outside the managed block solved it, yet this reveals that the helper and hook need a clearer shared mechanism for project-local exact denies. Third, the verification phase briefly tried to run a global daemon command from `/tmp`, which the Git-worktree hook correctly blocked. No state changed, but the command should have been routed through an initialized Git project from the start. None of these issues compromised the result; they did, however, lengthen the path. The future improvement is to preflight the execution environment—not just the corpus—before starting a long index job.

## Lessons Learned

- A direct embedding benchmark and a real index pilot answer different questions; both are needed before consequential migration.
- Provider-recommended prompt formats are not evidence that an integration can express them. Inspect the actual adapter boundary.
- Global model migration must be recorded separately from project-index readiness because dimensions make stale indexes unusable.
- Security-preserving mirrors are valid for a repository-scale pilot when source symlinks are intentional and the exact omission set is documented.
