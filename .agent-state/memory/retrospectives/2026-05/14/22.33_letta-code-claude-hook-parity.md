## Lessons Learned

- Treat hook copying as harness migration, not preference storage: use the harness configuration skill and keep behavior in `~/.letta/settings.json` or project/local `.letta` settings.
- Before copying hooks, inspect the source config (`~/.claude/settings.json`) and destination merged config (`show_config.py`) to avoid duplicates or contradictory policies.
- For user-level hook edits, copy scripts into `~/.letta/hooks/` rather than pointing Letta directly at `~/.claude`; this keeps ownership clear and makes future Letta-specific adjustments safer.
- Validate dependencies (`rtk`, `jq`), shell syntax (`bash -n`), and at least one sample stdin payload for command-rewriting hooks.
- Always create a timestamped backup of `~/.letta/settings.json` before direct JSON edits.
- Use precise claims: “configured + script-tested” is different from “verified in a fresh Letta runtime after hook reload.”
