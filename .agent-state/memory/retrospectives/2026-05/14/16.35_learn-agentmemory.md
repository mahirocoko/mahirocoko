## Lessons Learned

- For `/learn --deep`, treat a single long-running agent as suspect once the other four reports exist and the output file is still missing; cancel only that task and rerun with a tighter prompt.
- Always verify that learn docs are written outside `origin/` and that `git status --short` inside the cloned source is clean.
- For agentmemory specifically, the most important implementation insight is the full-server vs standalone-MCP split: proxy mode gives the full 51-tool surface, local fallback is intentionally limited.
- When explaining local-first tools, distinguish install-time network access, model-provider calls, mesh/OTLP sync, and default runtime storage. They are different risk categories.

## Next Steps

- If the user proceeds with installation, start with `npx -y @agentmemory/agentmemory` and verify `/agentmemory/health` plus the viewer before wiring MCP.
- Keep API keys and `AGENTMEMORY_AUTO_COMPRESS` off initially to preserve a local-first setup.
- If vector search is desired, prefer local embeddings first before adding external provider keys.
- If adding OpenCode MCP config, make sure `AGENTMEMORY_URL` points at the running full server so the shim does not silently fall back to local 7-tool mode.
