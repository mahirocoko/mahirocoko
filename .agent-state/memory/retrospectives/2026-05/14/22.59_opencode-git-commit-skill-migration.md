## AI Diary

I appreciated this session because it clarified an important boundary between similar but not identical agent runtimes. Mahiro's phrasing was casual — “ถ้ารองรับอะนะ” — but the underlying question was architectural: can Letta consume opencode command files directly, or should the command be re-expressed as a Letta skill? I first tested the installed CLI instead of guessing, which gave a concrete answer: the executable is `letta`, it has subcommands and headless mode, but there was no evidence of a direct opencode command loader. When Mahiro corrected the path to `~/.config/opencode/command`, I accepted it and inspected that exact source. The migration itself was small but important: the original opencode command used `git add -A` and “do not include AI attribution,” while Letta Code's active system policy says commits must be explicit, careful, and include Letta attribution when committing through me. I preserved the useful commitlint type+emoji style but adjusted the dangerous parts. This is exactly the kind of workflow translation that should become muscle memory: copy the intent, not every behavior blindly.

## Honest Feedback

Three friction points are worth recording. First, my first answer to “รองรับพวก command ไหม” was a bit too CLI-oriented; I tested `letta --help` correctly, but I should have immediately connected the result to the user's likely intent: slash/workflow commands versus executable CLI subcommands. Second, I initially searched both `~/.opencode` and `~/.config/opencode`, but the user still had to tell me the precise folder. The search did find it, yet I could have summarized that discovery before the user's correction landed. Third, the generated Letta skill is intentionally pragmatic rather than a literal copy. That is the right call for safety, but it means anyone comparing it line-by-line with opencode will see behavior differences: no default `git add -A`, no promise to omit AI attribution when system policy requires it, and no dependence on a missing `docs/commit-guide.md`. I should frame those as deliberate compatibility adaptations, not accidental divergence.

## Lessons Learned

- Letta Code supports reusable command-like behavior through skills, not by directly reading opencode `~/.config/opencode/command/*.md` files.
- When migrating commands across agent runtimes, preserve the workflow's intent and trigger phrases, but adapt safety-critical behavior to the destination runtime's policies.
- For git commit workflows in Letta, never carry over blind `git add -A` as the default; stage explicit paths after checking `git status`, `git diff`, and generated/secret risks.
- If an opencode command references repo docs such as `docs/commit-guide.md`, check whether the file exists in the active repo and provide a fallback from recent commit history if absent.
- A skill's `description` is the trigger surface; include `/git-commit`, `git-commit`, and `cmt`-style phrasing so future Letta sessions can discover it.
