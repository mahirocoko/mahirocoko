## Key Code Changes

- `block-secret-reads.py` now has `strip_heredoc_bodies(command)` and runs environment-dump regexes only against shell syntax outside heredoc bodies. This keeps `env` command detection while avoiding false positives from generated script content such as `#!/usr/bin/env python3`.
- `rtk-suggest-heavy.py` reads hook JSON, checks `tool_input.command`, ignores already-RTK commands, `RTK_DISABLED=1`, and heredoc commands, detects likely output-heavy command families, calls `rtk rewrite`, and exits `2` with a retry suggestion when RTK has a useful rewrite.
- Settings order is now: secret guard, RTK heavy suggestion, legacy RTK rewrite hook, Letta commit-attribution block.

## Architecture Decisions

- Do not rely on Claude-style `updatedInput` until Letta Code explicitly supports it for command hooks.
- Prefer a narrow deny-with-suggestion hook over broad blocking. It should catch common high-token commands (`git diff`, `git status`, `rg`, `ls`, tests, builds, linters, Docker/Kubernetes logs) while leaving exact low-output commands alone.
- Preserve an escape hatch: `RTK_DISABLED=1 <cmd>`.
- Keep `rtk-rewrite.sh` installed; if Letta Code later supports `updatedInput`, it can start working without rebuilding the whole RTK setup.

## What Could Improve

- I should have inspected the existing secret guard for heredoc handling before using heredoc-based script creation under a global shell guard.
- I initially described Letta’s `updatedInput` limitation from evidence in bundled JS, but that area should probably become an upstream issue or harness note if we want it fixed instead of worked around.
- The new RTK suggestion hook is heuristic. It is intentionally narrow, but it may still need tuning after real use.

## Blockers & Resolutions

- **Blocker**: `block-secret-reads.py` treated `/usr/bin/env python3` inside a generated file as a shell environment dump.
  **Resolution**: Strip heredoc bodies before scanning for environment-dump patterns.
- **Blocker**: Letta command hooks appear not to mutate command input from `updatedInput`.
  **Resolution**: Use memory/manual RTK preference plus a deny-with-suggestion hook for output-heavy raw commands.

## Honest Feedback

Three friction points stood out. First, the old RTK hook created a false sense of coverage: it was installed, executable, and produced the expected JSON, yet the host runner did not appear to apply the mutation. A config can be “valid” and still not effective, so future harness checks need an end-to-end proof, not just a script-output proof. Second, the secret guard’s `env` regex was too broad when applied to whole shell payloads including heredoc bodies. That kind of safety check should understand enough shell structure to avoid punishing normal script generation. Third, the deny-with-suggestion approach adds deliberate friction. It is useful because Letta lacks transparent rewrite right now, but if it fires too often on small commands, it will feel like the tool is scolding rather than helping. The next improvement should be observing real usage and pruning the heavy-command list rather than expanding it aggressively.

## Lessons Learned

- RTK integrations differ by host capability: transparent `updatedInput`, in-place plugin mutation, or prompt-only instruction.
- Letta Code should not be assumed to support Claude Code hook response semantics just because it uses similar event names.
- Safety hooks must treat heredoc bodies as data, not shell syntax, before scanning for dangerous commands.
- Deny-with-suggestion is a viable fallback when transparent rewrite is unavailable, but it should be scoped to high-token commands and include a clear escape hatch.

## Next Steps

- Use the new RTK suggestion hook for a few sessions and tune the command list if it blocks too much or misses common heavy commands.
- Consider opening/updating a Letta Code issue: `PreToolUse` command hooks should support `updatedInput` mutation for `ShellCommand`.
- If Letta gains `updatedInput`, remove or relax `rtk-suggest-heavy.py` and rely on transparent rewrite.
- Keep using `rtk` manually when exact compact output is desired without relying on hook retry.
