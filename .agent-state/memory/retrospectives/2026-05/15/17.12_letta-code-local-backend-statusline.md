## Lessons Learned

- In Letta Code `--backend local`, distinguish backend state locality from provider network and telemetry. “Local backend” means agent/conversation/message/local MemFS state uses `LocalBackend`; it does not inherently mean local-only inference or zero telemetry.
- Current statusline payload exposes conversation id as `session_id`, not `conversation_id`; scripts can read it today, but conversation name/title is not available in the current payload.
- When customizing a statusline, preserve existing situational context such as folder/project name unless the user asks to remove it.
- For Mahiro’s machine, avoid broad shell boilerplate that triggers hooks; use simple focused commands and recover by adapting to hook feedback.

## Next Steps

- If Mahiro wants stronger local privacy defaults, add a small wrapper/alias such as `LETTA_CODE_TELEM=0 letta --backend local` rather than relying on memory.
- If statusline needs conversation title, consider a future Letta Code patch adding `conversation: { id, name }` while keeping `session_id` for compatibility.
- If the new statusline feels too long, tune truncation/order rather than removing folder or conversation context.
