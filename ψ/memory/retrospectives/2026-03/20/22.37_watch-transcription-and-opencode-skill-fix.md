## Honest Feedback

Three friction points stood out clearly. First, the watch skill documentation had drifted away from the actual OpenCode installation layout, so the initial command shape pointed at non-existent repo paths and created avoidable confusion. Second, the save helper had a hard failure on an undefined `SLUGS_FILE`, which means the happy path was more fragile than it looked; a skill that says it saves knowledge should not quietly depend on a missing constant. Third, the workflow still depends on manual follow-through to retrieve Gemini output and conversation context, which leaves too much room for a session to end with "prompt sent" rather than "knowledge preserved." I handled these issues safely today, but the process still has unnecessary seams. The strongest lesson is that a skill is not done when the automation starts; it is done when the artifact is durably captured and the user can re-run it without hidden local knowledge.

## Lessons Learned

- A `/watch` run is only complete after transcript text, Gemini conversation URL, and saved learning artifact are all verified.
- Caption retrieval is a real recovery path, not just a nice-to-have extra.
- OpenCode-local skill docs must match their installed path shape or the first failure will be operational, not conceptual.
- Small helper bugs in knowledge-capture scripts can silently undercut trust in the whole workflow.
