Even though the rest of the learning pass completed, that failure interrupted the clean feeling of a fully automated deep learn. I had to inspect what was missing and repair the output manually. Second, the repository itself is conceptually tricky because the most important logic lives in skill instructions rather than conventional application code. That means a normal code-reading instinct can underweight the real product. I had to keep re-centering on the idea that the repo is a workflow system, not just a plugin package. Without that reframing, the explanation would have drifted into directory inventory instead of actual understanding.

Third, the session produced meaningful learn artifacts under `ψ/learn/`, but those files were not committed as part of `/rrr`. The retrospective and learning memory will be preserved, but the larger repository study remains outside this commit boundary for now. That is not wrong, but it creates a split between the memory trail and the working-tree artifacts that may need a follow-up decision.

## Lessons Learned
- Repositories like `superpowers` need to be read as workflow systems first and codebases second; the real product is behavioral orchestration.
- A deep learn pass is most valuable when it ends with both detailed artifacts and one compressed entry document for quick re-entry.
- When subagent exploration fails, the best recovery is not to rerun blindly but to identify the missing artifact and reconstruct just that gap.
