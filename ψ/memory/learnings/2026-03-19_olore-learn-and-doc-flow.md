# Lesson Learned: olore works because it makes documentation visible before it is needed

`olore` is not just a way to download docs. Its real design win is that it turns documentation into a shared local artifact that every coding agent can see and use consistently. The package is stored once in `~/.olore/packages/...`, then surfaced into each agent's skill directory through symlinks or platform-equivalent links. That means the same documentation package can appear naturally inside Claude Code, Codex, and OpenCode without duplicating content.

The more important insight is that `olore inject` solves the discovery problem. Agents often fail not because docs are unavailable, but because they do not realize docs exist at the moment they should consult them. By writing a documentation reference table into always-read files like `AGENTS.md` and `CLAUDE.md`, `olore` moves docs from optional retrieval into passive context. The user-facing explanation should therefore emphasize three concrete steps: docs are installed into a central local store, linked into agent skill folders, and then made discoverable through passive project context so the agent actually uses them.
