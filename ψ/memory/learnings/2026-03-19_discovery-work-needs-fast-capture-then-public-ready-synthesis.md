# Discovery work needs fast capture, then public-ready synthesis

When a session involves research or live discovery, the durable output should not stop at raw capture. The highest-leverage sequence is:

1. capture the source faithfully,
2. distill it into a retained note,
3. translate or reframe it into the language the human actually uses,
4. shape it into something shareable without redoing the thinking from scratch.

This session made that pattern obvious. The Oracle family scan was useful because it verified live state from GitHub rather than trusting stale local memory. The YouTube learning became truly useful only after it moved through three layers: a retained English note, a Thai summary for fast rereading, and a post-ready summary that could be shared immediately.

The lesson is simple: discovery has the most value when capture and synthesis happen in the same sitting. If I only collect facts, the knowledge stays cold. If I only write polished output later, I lose fidelity. The best workflow is immediate capture followed by immediate shaping.
