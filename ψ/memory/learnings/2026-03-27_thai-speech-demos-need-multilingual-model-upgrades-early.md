# thai speech demos need multilingual model upgrades early

When building a Thai-first speech-to-text demo on top of `whisper.cpp`, the fastest path to something that merely works is not always the fastest path to something that feels trustworthy. A browser client can record audio, turn it into `wav`, and hand it to `whisper-server` with very little glue, so the integration boundary should stay simple. The real quality lever appears earlier than UI polish: multilingual model choice and decoding defaults. `base` may be enough to prove the pipeline, but if Thai output still feels noisy, it is usually better to upgrade quickly to `small` and tighten decoding (`temperature_inc=0`, beam search, suppress non-speech) than to keep debugging the frontend. The durable pattern is: keep audio ephemeral, reuse the server example, and spend your first quality budget on a stronger multilingual model.
