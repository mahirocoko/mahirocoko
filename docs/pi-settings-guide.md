# คู่มือ Pi `/settings` — เรียงตามความจำเป็น

อ้างอิง **Pi 1.4.0 ที่ติดตั้งในเครื่อง Mahiro ณ วันที่ 22 ตุลาคม 2026** เมนูหลักมี **33–35 รายการ** โดยสองรายการเกี่ยวกับการแสดงภาพจะขึ้นเฉพาะ terminal ที่รองรับ

คู่มือนี้เรียงตามความจำเป็นสำหรับใช้งาน coding **ค่าที่แนะนำเป็นคำแนะนำ ไม่ได้เปลี่ยนการตั้งค่าในเครื่อง** ส่วนค่าที่ระบุว่าเป็นของเครื่องหรือ session เป็นข้อมูล ณ ตอนจัดทำ ไม่ใช่สถานะปัจจุบันตลอดไป

## วิธีปรับ `/settings`

- พิมพ์ `/settings` แล้ว **พิมพ์ชื่อเพื่อค้นหาได้เลย** ไม่ต้องเลื่อนหาทุกครั้ง
- ใช้ `↑` `↓` เลือกรายการ
- กด `Enter` หรือ `Space` เพื่อวนค่า หรือเข้าเมนูย่อย
- กด `Esc` เพื่อกลับ/ปิด **แต่ค่าที่เปลี่ยนไปแล้วส่วนใหญ่บันทึกทันที** ไม่ใช่ยกเลิกทั้งหมด
- `true` = เปิด / `false` = ปิด

## 1. ควรรู้ก่อน — มีผลกับวิธีทำงานของ AI

### 1) Default thinking level per model

กำหนดว่า **แต่ละโมเดลควรใช้ระดับการคิดเท่าไรเป็นค่าเริ่มต้น**

| ระดับ | เหมาะกับ |
|---|---|
| `off` / `minimal` / `low` | คำถามง่าย แก้จุดเล็ก ๆ งานที่เน้นเร็ว |
| `medium` | งาน coding ทั่วไป เป็นจุดเริ่มต้นที่ดี |
| `high` | Debug ซับซ้อน ออกแบบระบบ รีวิวที่ต้องไล่เหตุผล |
| `xhigh` / `max` | ปัญหายากจริง ๆ ที่ยอมรอนานขึ้นได้ |

ระดับสูงขึ้นอาจใช้เวลาและ reasoning tokens มากขึ้น **ไม่ได้แปลว่าต้องเปิดสูงสุดทุกงาน** และตัวเลือกขึ้นกับโมเดลด้วย

**แนะนำ:** ใช้ `medium` เป็นหลัก แล้วขยับเป็น `high` เมื่องานยาก

ถ้าจะปรับระหว่างทำงาน ใช้ `/thinking` หรือ `Shift+Tab` ได้ ไม่ต้องเข้า `/settings` ทุกครั้ง

**ในเครื่อง ณ ตอนจัดทำ:** ค่าเริ่มต้นที่บันทึกไว้ของ `gpt-6.1-sol` คือ `medium` แต่ runtime ของบทสนทนาที่ใช้จัดทำคู่มือนี้รายงาน `max` อยู่ ค่าเริ่มต้นกับค่าของ session ปัจจุบันจึงไม่จำเป็นต้องตรงกัน

### รายการสำคัญที่เหลือ

| เมนู | คืออะไร / ใช้ตอนไหน | แนะนำ |
|---|---|---|
| **Auto-compact** | เมื่อบทสนทนาใกล้เต็ม context จะสรุปส่วนเก่าและเก็บข้อความล่าสุดไว้ ทำให้คุยต่อได้ ไม่ได้ลบประวัติ session เดิม แต่รายละเอียดบางอย่างอาจหายจากสรุป | **`true`** |
| **Steering mode** | จัดการข้อความที่คุณส่งด้วย `Enter` ตอน AI ยังทำงานอยู่ โดย `one-at-a-time` ส่งเข้าทีละข้อความแล้วรอคำตอบ ส่วน `all` ส่งข้อความที่ค้างอยู่พร้อมกัน ไม่ใช่การหยุด tool กลางคันทันที | **`one-at-a-time`** ถ้าต้องการควบคุมทีละจังหวะ |
| **Follow-up mode** | จัดการข้อความที่ส่งด้วย `Alt+Enter` ให้รอจน AI จบงานรอบปัจจุบันก่อน แล้วค่อยรับงานต่อ เลือกส่งทีละข้อความหรือทั้งหมดได้เหมือน Steering | **`one-at-a-time`** |
| **Default project trust** | ถ้ายังไม่มีคำตัดสินจาก extension หรือ trust ที่เคยบันทึกไว้ จะให้ Pi ถามก่อนโหลด config, extensions และทรัพยากรของโปรเจกต์ หรือเชื่อถือ/ไม่เชื่อถือไปเลย | **`Ask`** ปลอดภัยกว่า `Always trust` |
| **Skill commands** | ทำให้เรียก skill ผ่าน `/skill:ชื่อ` ได้ การปิดตัวนี้เป็นการปิดคำสั่งลัด ไม่ใช่สวิตช์ปิดการค้นพบ skill ทั้งระบบ | **`true`** |
| **Hide thinking** | ซ่อนข้อความ thinking ที่โมเดลส่งมา **เปลี่ยนแค่สิ่งที่แสดงบนจอ ไม่ได้ลดระดับการคิดหรือค่าใช้จ่าย** สลับด้วย `Ctrl+T` ได้ด้วย | `true` ถ้าอยากให้แชตสะอาด / `false` ถ้าอยากดู |
| **Cache warming** | ส่งคำขอเพื่อช่วยรักษา prompt cache ของ provider: `off` ไม่ทำ, `streaming` ทำระหว่าง agent ทำงาน, `idle` ทำต่อระหว่างรอคุณด้วยเมื่อระบบประเมินว่ายังคุ้ม | เริ่มที่ **`streaming`** ซึ่งเป็นค่าเดิม ไม่จำเป็นต้องเปิด `idle` เพราะมีคำขอและ usage เพิ่มได้ |

> **Project trust ไม่ใช่ sandbox** — การเลือกไม่ trust ไม่ได้จำกัดว่า tools อ่านหรือแก้ไฟล์ที่ไหนได้บ้าง

## 2. ควรรู้เมื่อใช้ภาพ แชร์บทสนทนา หรือสนใจความเป็นส่วนตัว

### ภาพ: สี่ตัวนี้ทำคนละหน้าที่

| เมนู | คืออะไร / ใช้ตอนไหน | แนะนำ |
|---|---|---|
| **Block images** | ป้องกันไม่ให้ Pi ส่งภาพเข้าโมเดล ถ้าเปิดแล้ว งานดู screenshot หรืออ่านภาพจะทำไม่ได้ตามปกติ | **`false`** สำหรับงาน frontend/ตรวจภาพ |
| **Auto-resize images** | ย่อภาพใหญ่ก่อนส่งให้โมเดล โดยค่าทั่วไปจำกัดไว้ไม่เกิน 2000×2000 เพื่อช่วยเรื่องขนาดและความเข้ากันได้ | **`true`** ยกเว้นงานที่ต้องรักษารายละเอียดภาพและ provider รองรับ |
| **Show images** | แสดงภาพให้ **คุณเห็นใน terminal** ปิดตัวนี้ไม่ได้แปลว่าห้ามส่งภาพให้ AI | **`true`** ถ้า terminal รองรับ |
| **Image width** | ความกว้างภาพที่แสดงใน terminal หน่วยเป็นช่องตัวอักษร เช่น `60`, `80`, `120` ไม่ใช่ความละเอียดภาพที่ส่งให้โมเดล | เริ่ม **`60`** แล้วเพิ่มถ้าภาพเล็กไป |

จำสั้น ๆ: **Show = คุณเห็น / Block = AI ไม่ได้รับ / Auto-resize = ย่อก่อนส่ง / Width = ขนาดบนจอ**

### คำเตือนและการส่งข้อมูลออก

| เมนู | คืออะไร / ใช้ตอนไหน | แนะนำ |
|---|---|---|
| **Warnings → Anthropic extra usage** | เตือนเมื่อใช้บัญชี subscription ของ Anthropic แล้วมีโอกาสเข้า paid extra usage ไม่ใช่ตัวควบคุมวงเงินหรือปิดการคิดเงิน | **`true`** |
| **Session share destination** | เลือกปลายทางของ `/share`: `auto` ใช้ Radius ถ้าล็อกอินไว้ ไม่เช่นนั้นใช้ GitHub Gist หรือบังคับเป็น `gist` / `radius` | **`auto`** ถ้าไม่ได้มีข้อกำหนดเฉพาะ ต้องตรวจบทสนทนาก่อนแชร์ เพราะมี prompts, code และผล tools ได้ |
| **Install telemetry** | ส่งข้อมูล anonymous เกี่ยวกับการติดตั้ง/อัปเดต และมีผลกับ header ระบุ Pi บาง provider เป็นคนละ setting กับ analytics | เลือก **`false`** ได้ถ้าไม่ต้องการส่ง ไม่ได้เป็นตัวปิดการตรวจอัปเดต |

## 3. ปรับเพื่อใช้งานทุกวันให้สบายขึ้น

กลุ่มนี้ส่วนใหญ่ **ไม่ทำให้ AI เก่งขึ้นหรือคิดมากขึ้น** เลือกตามความถนัดได้เลย

| เมนู | คืออะไร / ตัวเลือก | แนะนำ |
|---|---|---|
| **TUI mode** | `fullscreen` ให้ Pi จัดการเต็มหน้าจอ โดย editor/status อยู่กับที่ ส่วน `regular` ใช้ scrollback ปกติของ terminal | ลอง **`fullscreen`** ก่อน ถ้าชอบเลื่อนประวัติแบบ terminal เดิมให้เลือก `regular` |
| **Theme** | เปลี่ยนสีหน้าจอ `system` อิงสี terminal ส่วน `automatic` เลือกธีมสว่าง/มืดแยกกันและสลับตาม terminal เมื่อรองรับ | **`system`** เป็นจุดเริ่มต้นที่ง่าย |
| **Fullscreen copy on select** | ลากเลือกข้อความแล้วคัดลอกอัตโนมัติใน fullscreen ถ้าปิด ใช้ `Ctrl+X` คัดลอก selection ได้ | **`true`** ถ้าชอบลากแล้วได้ข้อความเลย |
| **Fullscreen wheel scrolling** | จำนวนบรรทัดที่เลื่อนต่อ mouse-wheel event ใช้เฉพาะ fullscreen | **`auto`** ก่อน ถ้ายังช้า/เร็วค่อยกำหนดเลข |
| **Fullscreen scrollbar** | `auto` แสดงตามความจำเป็น, `always` แสดงตลอด, `hidden` ซ่อน ใช้เฉพาะ fullscreen | **`auto`** |
| **Autocomplete max items** | จำนวนรายการที่เห็นพร้อมกันในช่องแนะนำคำสั่ง/พาธ ไม่ใช่จำนวนรายการทั้งหมดที่ค้นหาได้ | **`7` หรือ `10`** ถ้าอยากเลือกได้ง่ายขึ้น ค่าเดิมคือ `5` |
| **Quiet startup** | `false` แสดงข้อมูลเริ่มต้นครบ, `header` เหลือหัวโปรแกรม, `true` ซ่อนทั้งหัวและรายการทรัพยากรที่โหลด | **`header`** ถ้าอยากเห็นเวอร์ชันแต่ไม่รก — เครื่องนี้บันทึกไว้เป็น `true` ณ ตอนจัดทำ |
| **Mermaid diagrams** | แปลง Mermaid เป็นแผนภาพตัวอักษร: `off` ไม่แปลง, `final` รอข้อความจบก่อน, `streaming` วาดระหว่างตอบ | **`final`** ถ้าไม่ชอบภาพขยับระหว่างเขียน หรือคง `streaming` ซึ่งเป็นค่าเดิม |

## 4. ความจำเป็นต่ำ — ปรับเมื่อมีความชอบหรืออาการเฉพาะ

| เมนู | คืออะไร / ใช้ตอนไหน | แนะนำ |
|---|---|---|
| **Double-escape action** | กด `Esc` สองครั้งตอนช่องพิมพ์ว่าง: `tree` เปิดต้นไม้บทสนทนา, `fork` แยก session จากจุดก่อนหน้า, `none` ไม่ทำอะไร | **`tree`** หรือ `none` ถ้าเผลอกดบ่อย |
| **Tree filter mode** | ตัวกรองเริ่มต้นของ `/tree`: `default`, `no-tools`, `user-only`, `labeled-only`, `all` | **`default`** หรือ `user-only` ถ้าอยากหาจุดที่ตัวเองเคยถามเร็ว ๆ |
| **Editor padding** | ช่องว่างซ้าย–ขวาของพื้นที่พิมพ์ ปรับได้ `0–3` ช่อง | **`0–1`** ตามความชอบ |
| **Output padding** | ช่องว่างซ้าย–ขวาของข้อความตอบ ผล tools และผลคำสั่ง เลือก `0` หรือ `1` | **`1`** อ่านสบายกว่า |
| **Fullscreen exit output** | ตอนออกจาก fullscreen ให้พิมพ์ประวัติลง terminal (`transcript`) หรือเหลือแค่คำแนะนำกลับเข้า session (`resume-hint`) ไม่ใช่การลบประวัติที่บันทึกไว้ | **`resume-hint`** ถ้าไม่อยากให้ terminal ยาว |
| **Collapse changelog** | ย่อรายการเปลี่ยนแปลงที่แสดงหลังอัปเดต ไม่ได้ปิดการอัปเดต | **`true`** ถ้าไม่อยากอ่านรายการยาว |
| **Terminal progress** | แสดงสถานะ progress บนแท็บ terminal ผ่าน OSC 9;4 เมื่อ terminal รองรับ | เปิดได้ถ้ามีหลายแท็บและอยากเห็นว่า Pi ยังทำงานอยู่ |
| **Show hardware cursor** | ใช้เคอร์เซอร์ของ terminal แทนที่ Pi วาดเอง อาจช่วยเมื่อใช้ IME แล้วตำแหน่งหน้าต่างเลือกคำผิด | คง **`false`** ก่อน เปิดเมื่อมีปัญหาหรือชอบ cursor แบบ terminal |
| **Clear on shrink** | ล้างแถวว่างเมื่อเนื้อหาบนจอหดลง อาจช่วยเรื่องรอยข้อความค้าง แต่ทำให้กระพริบได้ | **`false`** เปิดเฉพาะเมื่อเจอปัญหาการวาดจอ |

## 5. ปล่อยค่าเดิมได้ — เครือข่ายและการวิเคราะห์ปัญหา

| เมนู | คืออะไร / ตัวเลือก | แนะนำ |
|---|---|---|
| **Transport** | วิธีรับส่งข้อมูลกับ provider: `sse` สตรีมผ่าน HTTP, `websocket` ใช้การเชื่อมต่อ WebSocket, `websocket-cached` ใช้ความสามารถต่อบริบทที่ provider รองรับ, `auto` ให้ระบบเลือก ไม่ใช่ทุก provider รองรับทุกแบบ | **`auto`** เปลี่ยนเมื่อแก้ปัญหาการเชื่อมต่อโดยเฉพาะ |
| **HTTP idle timeout** | ยอมให้ HTTP เงียบนานเท่าไรก่อน timeout **ไม่ใช่เวลาสูงสุดของงานทั้งหมด** เช่น `5 min` หมายถึงไม่มี headers/ข้อมูลใหม่ต่อเนื่องห้านาที | **`5 min`** ค่าเดิม ใช้ `disabled` เฉพาะกรณีจำเป็น เช่น local model ที่เงียบนานจริง ๆ |
| **Cache miss notices** | แสดงข้อความวิเคราะห์ cache miss, ค่าใช้จ่าย cache และการกู้คืนจากปัญหา provider เปิดแล้วไม่ได้ทำให้ cache ดีขึ้นเอง | **`false`** เปิดตอนสงสัยว่า token/cost สูงผิดปกติ |

**เริ่มจากระดับ thinking, Auto-compact และวิธีส่ง Steering/Follow-up ก่อนก็พอ** ที่เหลือค่อยปรับเมื่อรู้สึกติดขัด ไม่จำเป็นต้องไล่เปลี่ยนให้ครบทุกตัว
