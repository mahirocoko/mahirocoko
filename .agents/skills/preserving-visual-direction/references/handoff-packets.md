# Handoff packets

Use these shapes to preserve direct evidence. Replace placeholders with repo facts and Mahiro's exact request; do not add a main-authored visual interpretation.

## Raster vision preflight

```text
Read-only preflight. Open the attached raw references directly. Do not write files.

Return only objective source identity:
1. exact visible primary headline
2. section order
3. major visible product surfaces in each section
4. any text/anatomy you genuinely cannot read

Do not redesign, improve, infer hidden behavior, or use a prose summary from another agent.
References: <direct attachments or proven image-input paths>
```

Fail the gate when the answer invents a headline, section, or product surface. Do not send the correct answer back as a visual brief.

## Visual-owner implementation packet

```text
Human request (verbatim): <request>
Target: <repo-relative-target>
Technical scope explicitly supplied by human/repo: <scope>
Product-truth sources: <paths>
Raw visual references: <direct attachments/paths>
Accepted baseline: <identity or none>
Rejected/non-authoritative baselines: <identities>

You own the complete bounded visual implementation. Inspect the raw evidence directly.
Do not ask the coordinator to summarize the visual direction.
Do not inherit visual decisions from rejected baselines.
Return raw desktop/mobile/state renders for the human gate before reviewer polish.
Do not commit or push unless the human explicitly requests it.
```

Do not append generic constraints such as offline-only, system fonts, no packages, extra interactions, accessibility features, or visual invariants unless the human or repo supplied them.

## Production-owner packet

```text
This is a source-locked production pass, not a design task.
Visual lock: <path>
Accepted source: <paths/ref/hashes>
Accepted renders: <paths/hashes>
Required visual preflight: open every accepted desktop/mobile/state render before writes.
Allowed production changes: <narrow-list>
Protected visual/copy/assets: <list>
Required technical checks: <repo-local-checks>
Required deterministic comparisons: <viewports/states>

Preserve composition, copy fit, typography, tokens, spacing, motion personality,
responsive anatomy, assets, and rendered output. If correctness requires a visible
change, stop and route that decision to Mahiro or the visual owner.
Do not commit or push unless the human explicitly requests it.
```

## Verification packet

```text
Read-only verification. Attempt to disprove preservation and correctness claims.
Use the visual lock and exact capture contract. Do not redesign or propose polish.

Report separately:
- source/render identity
- full-page and per-state visual differences
- baseline repeat variance
- fonts/assets/media readiness
- overflow/console/interaction/accessibility findings
- uncovered scope

Never mark human-owned visual acceptance complete.
```

## Validated historical pattern

`apps/agent-halo-sol-notch-simulator` validated the role split: Gemini 3.5 supplied an optional interaction seed, Kimi K3 integrated it into an accepted whole-page codebase, and Sol production-hardened typed state truth, keyboard/live-region behavior, intrinsic media, and mobile focus handling without CSS drift. Full-page desktop/mobile differences were zero; small per-state differences stayed below measured repeated-capture variance. This is evidence for role separation, not a universal style or model capability claim.
