Create one mobile-first static HTML flow prototype for a Thai personal income/expense app called `สมุดเงิน`.

Output rules:
- Return only HTML. No Markdown fences.
- Use plain HTML and embedded CSS in a `<style>` tag.
- No JavaScript, frameworks, build tools, CDNs, external fonts, or external images.
- Set `<html lang="th">`.
- Build a mobile-first responsive app flow that reads comfortably on a phone first, then expands cleanly on tablet and desktop.
- Do not cram every feature into one page. Split the experience into focused screens/sections that represent the product flow.

Design direction:
- Use a Wise-inspired fintech design system with restraint: warm off-white canvas, near-black text `#0e0f0c`, Wise Green `#9fe870` for the primary CTA and important affordances, dark green `#163300` button text, mint surface `#e2f6d5`, thin borders `rgba(14,15,12,0.12)`, minimal shadows.
- Use `Wise Sans` if available with Inter/system fallback. Use `font-feature-settings: "calt" 1`.
- Display headings can be bold, but keep Thai readability and normal product hierarchy stronger than billboard scale. Use generous line-height and enough spacing that Thai text feels calm on mobile.
- Buttons, cards, form controls, and tags should use normal console radii around 8–12px. Do not use transform hover animations.
- Each screen should have one job. Keep the home screen light: overview, one primary action, recent activity, and the next important reminder only.
- Move secondary detail into dedicated screens, dialogs, bottom sheets, or modal-like sections instead of placing everything on the home screen.
- Make the ledger a dedicated working surface with mobile-friendly list rows by default. Keep summary information compact instead of opening with a generic metric-card grid.
- Do not use glassmorphism, gradients, dark SaaS styling, decorative charts, fake security seals, oversized dashboard hero blocks, or generic KPI filler.

Content requirements:
- Home screen: mobile-first top bar with `สมุดเงิน`, month `เมษายน 2569`, status `ข้อมูลตัวอย่าง — ไม่เชื่อมต่อบัญชีธนาคาร`, and primary action `บันทึกรายการ`.
- Main heading: `เห็นเงินเข้า เงินออก และเงินคงเหลือในเดือนนี้`.
- Home summary: make remaining balance the main focal point, then show income, expenses, and savings goal as compact supporting items. Format Thai Baht amounts like `฿18,450.00`.
- Quick entry flow: present type, amount, category, note, date, and save button as a focused dialog, bottom sheet, or dedicated entry screen.
- Ledger screen: use mobile-friendly list rows by default, with Buddhist Era dates such as `29 เม.ย. 2569`, Thai categories, notes, and right-aligned amounts. On wider screens this may become a table.
- Summary screen: category budget rows with text equivalents, e.g. `อาหาร/เครื่องดื่ม ฿4,250 · 32% ของรายจ่าย`.
- Reminder/settings flow: upcoming bills, debt installment, savings goal, backup/export/privacy actions should be secondary surfaces, not all visible on home.

Accessibility:
- Include skip link, semantic landmarks, labeled inputs, visible focus states, and strong contrast.
- Do not rely on red/green alone; pair color with `รายรับ`, `รายจ่าย`, `+`, and `−` text.
- Keep Thai line-height generous and avoid tight letter spacing.
- Avoid tiny labels, cramped tables, four-equal-card KPI grids, stuffed home screens, and layouts that only work well on desktop.
