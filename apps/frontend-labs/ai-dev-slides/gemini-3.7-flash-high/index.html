03 / PARADIGM SHIFT

จากก๊อปคำตอบเอง สู่ให้ agent ลงมือใน repo

AI Chat

Manual Copy-Paste Loop

มนุษย์เป็นสะพานเชื่อมระหว่าง Chat, Editor และ Terminal
1 เจอ error
↓ ก๊อปปี้ไปวางในแชต
2 ก๊อปไปถาม
↓ รอคำตอบแล้วคัดลอก
3 ก๊อปคำตอบกลับมา
↓ สลับไป terminal/IDE
4 รันเองใน terminal

Claude Code

Autonomous Repo Execution

Coding Agent ตัวแรกที่ลงมือและจัดการลูปการทำงานใน Repo จริง
1 อ่าน codebase
↓ เข้าใจบริบทและ dependencies
2 แก้ไฟล์
↓ แก้ไขตาม requirement
3 รัน command และ test
↓ ประเมินผลลัพธ์อัตโนมัติ
4 อ่านผลแล้วทำต่อได้
✓ วนรอบแก้ปัญหาและ verify ผลได้โดยตรง
04 / THE MEMORY PROBLEM

ก่อน Letta ผมลองสร้าง memory layer เอง

CODING AGENT
Claude Code
↕ MCP (Model Context Protocol)
EXTERNAL PERSISTENCE
Memory layer ข้าม session
แยก Memory ออกจาก Coding Tool เพื่อให้ Context คงอยู่เมื่อเปลี่ยนเครื่องมือ
  • อยากให้ agent ค้นและดึง context จากงานก่อนหน้ากลับมาใช้ได้

    เรียกความจำ ประวัติการตัดสินใจ และ context ของโปรเจกต์เดิมมาต่อยอด

  • ไม่อยากเริ่มใหม่จากศูนย์ทุกครั้งที่เปิด session

    ลดเวลาที่ต้องคอยป้อน prompt อธิบายสไตล์หรือข้อตกลงซ้ำ ๆ

  • ลองแยก memory ออกจาก coding tool เพื่อไม่ให้ข้อมูลผูกติดกับเครื่องมือเดียว

    อิสระในการสลับ runtime หรือ model โดยความรู้สะสมไม่สูญหาย

04

06 / DUAL-CORE ARCHITECTURE

Letta Code เป็นตัวหลัก แต่ workflow ไม่ได้ผูกกับตัวเดียว

MAIN AGENT

Letta Code — main agent ที่รู้จักผม

ตัวตนหลักที่คุย ประสานงาน และเก็บ context ต่อเนื่อง

  • ✦
    รู้จัก workflow, preference และวิธีทำงานของผม

    เข้าใจสไตล์และมาตรฐานส่วนตัวโดยไม่ต้องอธิบายใหม่

  • ✦
    มี persistent memory จำ context ข้าม session

    หน่วยความจำถาวรช่วยต่อยอดงานและเก็บบทเรียนระยะยาว

PORTABLE PROCEDURES

Skills — workflow ที่พกไปใช้กับ agent อื่นได้

ขั้นตอนการทำงานมาตรฐานที่นำไปรันกับ Agent ตัวใดก็ได้

  • ✦
    ใช้ procedure เดิมกับ Agy, OpenCode, Claude Code และ CLI อื่น

    แชร์ชุดทักษะร่วมกันข้ามสารพัด Harness และ Agent

  • ✦
    เปลี่ยน model หรือ tool ได้ โดยไม่ต้องเริ่มวิธีทำงานใหม่ทั้งหมด

    Workflow ยืนยาวกว่าตัว Model และ Tooling เสมอ

ℹ
เส้นแบ่งทางสถาปัตยกรรม: Skills เป็น Portable Procedure ที่พกไปใช้ข้าม Agent ได้ ส่วน Mods ใช้ขยาย Runtime ของ Letta Code โดยเฉพาะ
07 / MULTI-AGENT DIVISION OF LABOR

ผมแบ่งงานให้ agent ยังไง

บทบาท หน้าที่ เลือก model แบบไหน
Main / Coordinator
คุย วางแผน ถือ context ภาพรวม คิดรอบคอบ รองรับ context ยาว
Scout
อ่าน codebase กว้าง ๆ สรุปจุดสำคัญ อ่านเร็ว สรุปชัด จับ pattern ได้
Writer
ลงมือแก้ code ใน scope ที่ชัดเจน แม่นยำ ทำตาม instruction เคร่งครัด
Reviewer / Verifier
ตรวจ code, command และผล test ช่างสงสัย หาจุดขัดแย้งและ edge cases เก่ง
Visual Direction
สำรวจและทดลองทิศทางด้านภาพ รสนิยมและ creative taste เข้ากับงาน
เลือก Model ตาม บทบาทของงาน แทนการหา Model ตัวเดียวที่เก่งที่สุดทุกเรื่อง
08 / EXECUTION LIFECYCLE

หนึ่งงานจริง ผมเริ่มและจบยังไง

STEP 1 Ground Reality

ดูของจริงใน repo

(code, config, logs)

STEP 2 Scope

กำหนดเป้าหมายและ scope ให้ชัด

STEP 3 Procedure

เลือก skill หรือ workflow ที่เกี่ยวข้อง

STEP 4 Roster

เลือก agent และ model ที่เหมาะกับบทบาท

STEP 5 Iterate

ลงมือแก้ทีละส่วน พร้อม verify ผลจริง

STEP 6 Human Gate

review ผลลัพธ์สุดท้ายและตัดสินใจเอง

STEP 7 Memory

บันทึก context หรือปรับ skill ไว้ใช้ครั้งถัดไป

↻
Continuous Learning Loop: สิ่งที่เรียนรู้ใน Step 7 จะกลายเป็น Context และ Skill ที่พร้อมใช้สำหรับงานถัดไปทันที
09 / MULTI-AGENT OBSERVABILITY

เปิดหลาย agent พร้อมกัน ผมดูและคุมยังไง

EXECUTION CONTROL ROOM

Herdr — control room สำหรับ agents

  • จัด workspace, tab และ terminal pane

    แบ่งแยกสภาพแวดล้อมและ lane ของแต่ละงานอย่างเป็นสัดส่วน

  • ส่ง prompt อ่าน output และหยุดงาน

    สั่งงานและแทรกแซง execution ได้ทันทีเมื่อจำเป็น

  • สลับกลับไปยัง pane ที่ต้องการได้ทันที

    กระโดดเข้า context ของ agent ตัวที่ต้องการโดยไม่หลงทาง

AMBIENT NOTCH MONITOR

Agent Halo — สถานะบน Notch

working
waiting
done
error
  • แสดงสถานะ working, waiting, done, error

    เห็นภาพรวมการทำงานของทุก agent ในระดับสายตา

  • เหลือบดูได้โดยไม่ต้องเฝ้า terminal

    ลด Cognitive Load ทำงานอื่นคู่ขนานได้อย่างมั่นใจ

  • คลิกกลับไปยัง session นั้นได้ทันที

    คลิกจาก Notch เพื่อเปิด Terminal Pane ที่กำลังรอ input ได้ตรงจุด
