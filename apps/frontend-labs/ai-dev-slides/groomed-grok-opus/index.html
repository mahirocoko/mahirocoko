New project

สร้าง context ให้โปรเจกต์ใหม่

  1. 01
    เลือก stack และวาง structure

    เริ่มจากของที่โปรเจกต์ต้องใช้จริง

  2. 02
    mahiro-style

    ใช้เป็น doctrine ตอน repo ยังไม่มีกติกา

  3. 03
    mahiro-docs-rules-init

    สร้าง AGENTS.md และ project docs

  4. 04
    cocoindex-rules-init → ccc

    ตั้ง safe exclusions ก่อน index และ search

พอมี docs แล้ว กติกาใน repo คือ source of truth

Existing project

โหลดของจริงก่อนลงมือ

  1. recap รู้งานค้าง จุดตัดสินใจ และสิ่งที่ควรทำต่อ
  2. AGENTS.md · docs · git status อ่านกติกาและงานที่มีอยู่ก่อน
  3. current behavior ดู source · browser · logs · failing command
  4. ccc / exact search หา owner และ pattern ที่ใช้อยู่จริง
กติกาเดียว mahiro-style เติมช่องว่าง ไม่ทับ local pattern

Execution loop

พอเข้าใจงานแล้ว ใช้ลูปเดียวกัน

  1. 01กำหนดจุดที่นับว่าจบ
  2. 02main ทำเอง หรือแบ่งงาน
  3. 03implement แล้วรวมผลกลับมา
  4. 04verify จาก evidence จริง
  5. 05Mahiro review — ผ่านหรือแก้ต่อ

Choose the execution path

เพิ่ม orchestration เท่าที่งานต้องใช้

  1. 01
    Letta Code — Main ทำเอง

    scope ชัด · มี concrete anchor · ไม่ต้องแยก exploration

  2. เมื่อ role หรือ context ต้องแยก
  3. 02
    Letta subagent

    Scout · Writer · Reviewer · Verifier

    แยก context โดยยังอยู่ใน workflow เดิม
  4. เมื่อ capability เฉพาะ executor จำเป็น
  5. 03
    Direct executor lane

    Agy · Cursor · Codex · Pi

    Herdr คุม pane · Agent Halo ดูสถานะ

ใช้ได้ทุกชั้น

  • ccc / exact searchหาของจริงใน codebase
  • Playwright / HiroHiroเก็บ browser evidence
  • Mahiro Skillsprocedure ที่พกข้าม agent

เริ่มจากทางที่เบาที่สุด แล้วเพิ่ม orchestration เมื่อมีเหตุผล

Learn from source

ติดตรงไหน ไปเรียนจากของจริง

Trigger เจอปัญหาที่ติดอยู่
หรือเจอ repo ที่น่าจะช่วยได้
  1. project หา · clone · track source
  2. learn อ่าน architecture · patterns · commands · gotchas
  3. Keep · Adapt · Reject ตัดสินจากหลักฐาน ไม่ copy ทั้ง repo

กลับมาใช้กับ project ของเรา ↵

Close the loop

จบงานแล้ว เก็บอะไรไว้ใช้ต่อ

  1. rrr ย้อนดูว่าอะไรเวิร์ก พลาด และควรจำต่อ
  2. mahiro-guidance-refine เปลี่ยน feedback เป็นข้อเสนอแก้ AGENTS.md, docs และ rules
  3. auditing-context-contracts เช็ก code, comments, docs และ memory หลังเปลี่ยน contract ใหญ่
  4. git-commit อ่าน status, diff และ commit style — ทำเมื่อสั่งเท่านั้น
  5. forward ส่ง handoff ถ้างานยังไม่จบแต่ต้องเปลี่ยน session

งานจบหนึ่งรอบ → workflow รอบถัดไปดีขึ้น
